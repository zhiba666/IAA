**抖音 IAA 小游戏 UI 与玩法调研——《小小爆米花厂》下一步开发建议**

调研日期：2026-09-06。结论：现有项目已经具备完整的轻经营骨架；下一轮最值得投入的是让“火候、爆开、本单完成”在画面上变得直观，再验证是否需要更深的操作。先做好一锅和一单，之后扩展口味、客户与长期收集。

本文中的竞品事实、Chrome 观察、代码发现和设计建议分别注明。建议属于待验证方案，不代表上线效果承诺。

**3．实际界面观察：该学的是信息表达和动作结果**

《我来掌勺》的近期实录能看到菜名与计时、中央制作区域、底部帮助入口，以及醒目的成功状态与返回选关。其价值在于制作对象和完成结果有明确的视觉位置；复杂、鲜艳的外框和大量内容页不必移植。[实录：制作鱼香肉丝，2026-08-24](https://www.douyin.com/video/7677607043939915334)

《爆个爆米花》的已见片段把容器与颗粒放大，主体占据大部分竖向空间，背景对比明显弱于前景。顶部承担少量状态，底部集中道具。建议参考这一视觉层级，但不能仅凭画面判断道具收益、广告频率或后续关卡体验。[实录](https://www.douyin.com/video/7609162287086017955)

本地工厂的优势是文字清楚、主按钮稳定、当前目标突出，普通领取与广告领取的金额都可读。需要继续改进的是：
- 场景中浅绿空背景较多，锅体、桶和颗粒相对偏小，玩家的注意力容易停在按钮与数字。
- “92–98点火”需要读数字；已有最佳区标记只是能量条下方的一条3像素细绿线，形态与锅体状态的关联不强。
- 订单页呈现了奖励和累计产量，却缺少客户、产品与“这一单完成了什么”的实物表达。
- 当前面板文字风格统一，但订单、升级、工厂之间的题材特征还可以更鲜明。

以上是本次Chrome与代码观察，不是玩家偏好统计。

| 界面部分 | 下一步建议 | 具体意图 |
| --- | --- | --- |
| 顶部余额和自动收入 | 保留现有位置，主数字与辅助单位保持层级 | 避免通过改版重新增加理解成本 |
| 当前目标卡 | 保留一项主目标；订单目标带客户小图与本单进度，完成后直接指向领单 | 让目标对应看得见的结果 |
| 生产场景 | 放大锅体和成品桶，压缩无信息留白；增强玉米色、焦糖色与背景的对比 | 让食物成为视觉主体 |
| 火候提示 | 将现有细绿线加强成条内高亮区、区间边界与文字状态；锅体振动/蒸汽同步 | 用“火候到了”承接操作，而非依靠记忆92–98 |
| 点火按钮 | 等待、可点火、成功、已尝试四态明确；位置稳定，成功后给本锅结果预期 | 降低误判与追数字的负担 |
| 订单页 | 加客户/用途、成品预览、本单阶段进度、交付反馈；保持清晰的普通奖励 | 奖励不再只是孤立的大数字 |
| 升级卡 | “推荐理由＋收益变化＋与当前目标的关系”；必要时建议攒钱 | 防止小升级与换代目标互相拉扯 |
| 换代页 | 继续使用已有前后机器预览，补充下一锅的具体工作差异 | 让升级产生即时期待 |
| 四个导航入口 | 保留，不再加一排常驻活动入口；次级内容归入已有面板 | 保持单指操作与主循环集中 |
| 广告入口 | 清楚标记视频与具体奖励；与生产/点火高频区域分离 | 用户能主动选择，不利用惯性点击 |

颜色不宜独自承担含义。例如点火和广告都可能用金黄强调，必须同时用图标、文案和位置区分。最佳火候也要有文字与边界提示，不能只靠绿色。

**4．玩法意见：在现有点火上深化，先验证一个变化**

现有循环已经是：生产并自动出售 → 获得金币 → 升级 → 累计产量达标 → 订单额外领奖 → 机器换代。推荐保留这一骨架，在每锅增加更清楚的操作预期和结果。

第一步做“现有点火更好懂”，先不改原数值：
1. 蓄能阶段：锅体、蒸汽、能量条表达同一状态。
2. 可操作阶段：清楚提示“进入最佳火候区再点火”，保留每锅一次。
3. 成功阶段：锅体闪亮、颗粒或喷发形态出现可辨识差异；提示本锅额外产量。
4. 结果阶段：爆锅实际发生后，展示这锅成果并回到生产；不要把成功提示与奖励到账混为一个时刻。
5. 失误阶段：仍按现有规则正常免费爆锅，不扣钱、不减产、不强制看广告。

当前配置为每秒自然增加1能量，每次点击增加2能量。以平均每秒r次点击估算，92–98窗口约为6/(1+2r)秒：放置约6秒，每秒2次点击约1.2秒。实际点击是每次跳2点，不是匀速。这意味着高频生产玩家的点火难度更高；应该观察玩家是否为了命中而停下生产，再决定是否把“火候指针”与产能点击解耦。不能直接把它称为漏洞，也不能未经体验就扩大窗口。

第二步才比较一个可选原型：“自动装袋”与“短装袋操作”。首轮只做一种容器，一个清晰的目标区，比较玩家是否自发想继续下一锅。不要同时叠加点火、接料、摇锅、调味四套操作。若装袋只是多一步手续，则保留自动表现。

第三步把订单做出小差异。建议先试3类自创订单：
- 街角小客：标准装袋，短目标，强调第一次完整交付。
- 影院补货：连续数锅完成一批，完成后箱子或货架留下可见成果。
- 派对定制：在两种包装或口味中选择，先验证结果偏好，再考虑经济差异。

这些客户与需求是新方案，不是已经存在的项目功能。开始时可以只改变目标表达、反馈与收集，不引入独立库存和复杂供应链。

**一个必须保持准确的语义：订单不是待售库存。**

现有生产即售出；订单按累计产量发额外奖励，领单不扣累计产量。代码已提供stageProgress，适合表达“本单完成度”。

例：上一单目标50，当前单目标200，累计生产80；当前单新增需求150，已推进30，本单进度20%，不是累计比例40%。进度容器应标“本单进度”，不能标“待售库存”。若超产已满足下一单，切单后应立即显示真实进度，不能强制重走空桶动画。普通生产粒子也不是一粒对应一份库存。

关于推荐升级，不能只把“最便宜”替换为“每秒收入回本最快”：点击升级需要考虑主动操作频率，订单与换代又有额外收益。第一版可先用明确目标规则与推荐理由，后续再比较预计达成目标的时间。回本和预计时间均需说明所用操作假设。

关于长期目标，目前三条升级最高Lv24、机器最多6阶段，循环单基本是需求乘1.35、金币乘1.3。难度继续提高而金币用途有限，难以单靠数值支撑长期兴趣。推荐先做一个“收集成果”的理由，不同时加签到、战令、排行榜、公会和多货币。

**6．IAA设计：奖励要改变接下来能玩的内容**

项目已经保留普通免费路线，并展示具体奖励与确认时冻结的报价，这是可继续使用的基础。当前用户已确认永久收益以及移除120秒激励冷却；本报告不将恢复旧冷却作为默认开发方案。

| 已有广告 | 更合适的表达与观察点 |
| --- | --- |
| 订单加价 | 同时展示普通金额、额外增加、总领取；观察是否帮助完成一个明确升级 |
| 离线翻倍 | 先让玩家看懂离线成果，再选择普通领或翻倍领；不要一回归就连续叠多个窗口 |
| 涡轮增压 | 对应“完成这一批”的短目标，并清楚说明持续时间与加速范围 |
| 设备赞助 | 表达离下一设备还差多少，以及赞助的实际帮助 |
| 品牌合作 | 保留永久产量含义，区分基础加成百分点与相对当前收益的增幅，避免误解 |

此前固定策略模拟中，“仅永久广告”为10条、总29分20秒；“永久+临时”为33条、总29分16秒。它提示需要检查收益叠加与广告时间占用；不能据此推断真实玩家的广告偏好、留存或收入。该模拟未领取成长任务，也未纳入最新点火策略。[模拟条件与结果](C:/Users/chenweilun/Documents/GitHub/IAA/docs/BRAND_PARTNERSHIP.md:42)

对UI直接有影响的现行平台要求：
- 看与不看广告的按钮应同时出现、等大、邻近；取消不能只做小字，也不能默认选择观看。
- 广告标识应使用官方规定样式，清楚可辨；与文案同行时放左侧。当前本地按钮主要为“广告 ·”文字，正式版应对照官方素材核查。
- 奖励应前置说明，完整观看兑现对应奖励，中途关闭不提前发奖；广告不能让计时玩法遭受负面结果。

上述依据[抖音广告审核FAQ](https://developer.open-douyin.com/docs/resource/zh-CN/mini-game/guide/contactus/ad)。因此不照搬部分竞品“大广告按钮＋很小跳过”的布局。

插屏只能考虑自然停顿点，并遵守启动前30秒不得展示、两次插屏至少间隔60秒、激励展示后至插屏至少间隔60秒等约束。满足间隔并不意味着应立刻展示；生产与点火过程中不应被插屏打断。[小游戏行为规范](https://developer.open-douyin.com/docs/resource/zh-CN/mini-game/operation1/norms/game-rule)

用户评论可以揭示设计问题：猫咪整理师的部分iOS玩家反映提示广告把一关切碎、正确位置的容错不足。这支持把“连续完成一段体验”作为观察重点，不支持从评论估算流失率，也不支持直接指认抖音版存在相同问题。[评论来源](https://apps.apple.com/cn/app/猫咪整理师-房间造景布置小屋-整理收纳达人/id6752363458)

**7．建议按三个阶段推进**

| 阶段 | 范围 | 可交付结果 | 进入下一阶段的依据 |
| --- | --- | --- | --- |
| A：先让现有玩法易懂 | 主体尺度、最佳火候提示、完美爆锅反馈、本单进度；推荐理由与目标一致 | 一版可玩的UI改进，普通生产与现有奖励规则稳定 | 新玩家能指出当前目标、最佳点火区、这一单是否完成 |
| B：验证一个新操作 | 自动装袋与单一短装袋原型对比；小规模客户/成品表现 | 一个可比较的玩法实验 | 玩家愿意继续下一锅，操作没有变成负担，免费推进没有明显受损 |
| C：补长期目标 | 一套口味/包装收集，少量主题订单，换代工作差异 | 有第二次打开理由的内容增量 | 内容可持续制作，奖励有用途，复访观察支持继续扩展 |

工作量不按未经拆解的日历承诺。A阶段可以继续拆成两个独立改动：先“火候＋本单进度”，再“推荐目标一致性”，使每次观察都能归因。

**8．怎样判断改动有价值**

建议先做5–8名新玩家的定性观察，覆盖连续点击、低频操作两种自然方式；不把这个人数当成统计显著性样本。记录：
- 能否自行开始生产、找到升级、理解自动收入和普通领单。
- 看见火候提示的锅数、可参与的锅数、实际尝试、成功，以及为什么没参与。
- 是否分得清“本单进度”“累计生产”“金币余额”。
- 是否因为推荐升级而不知道要不要攒钱。
- 一锅完成后是否主动继续；退出是没目标、等待太久、操作负担还是其他原因。

点火参与率的分母应是实际有机会参与并看到提示的锅数，不能拿全体启动人数；广告完成率应区分点击、请求成功、展示、完成与发奖。切后台、读弹窗和工具停顿要独立记录。首次事件同时看中位数、分布及失败原因，不能只报一个最快用时。

现有本地体验记录可复用，但它还不是联网分析平台。真实投放后，再按入口与新老用户拆分首局推进、复访和广告表现；不得用模拟广告完成率替代真实数据。官方启动分析也区分首帧与可交互，可交互场景上报ID为7001。[启动数据说明](https://developer.open-douyin.com/docs/resource/zh-CN/mini-game/operation1/about-data/performance-analysis/startup-data)

本地验证建议覆盖320×568、390×844，以及点火禁用不穿透、正常成功/失误、超产连续领单、弹层返回等实际风险。官方性能标准按系统、机档和品类区分，并说明帧率均值仅供参考；内部可以定更严格目标，但不能称“所有IAA都必须3秒/60帧”。[性能评测标准，2026-06-01更新](https://developer.open-douyin.com/docs/resource/zh-CN/mini-game/develop/guide/performance-optimization-both/performance-optimization/game-performance-standard)
