## 1. 先取得本小游戏的账号配置

在[抖音开放平台](https://developer.open-douyin.com/)登录负责本小游戏的开发者账号，进入对应小游戏，确认游戏名称和主体归属。已有小游戏时复用其 AppID，避免为联调重复创建应用。若账号中没有该小游戏，先完成小游戏创建所需资料；涉及主体认证、结算资料和协议的内容应由账号负责人核对。

| 本项目字段 / 权限 | 在平台核对什么 | 本地如何使用 |
| --- | --- | --- |
| `appId` | 对应的是“小小爆米花厂”的小游戏；官方指引从「开发管理 → 开发设置」获取 | 写入根目录 `config.local.json` |
| `rewardAdUnitId` | 已开通流量主，创建并启用激励视频广告位，归属上述小游戏 | 同一激励广告位服务游戏内四类奖励 |
| `interstitialAdUnitId` | 创建并启用插屏广告位，归属上述小游戏 | 仅用于阶段结算处的插屏 |
| IDE 开发权限 | 登录 IDE 的账号是该小游戏的开发者或有相应 IDE 权限的协作者 | 权限在平台设置，不存在可替代它的本地配置字段 |
| 测试账号 / 设备权限 | 负责扫码的抖音账号已绑定或添加为该应用的测试账号 / 设备 | 由手机抖音扫码完成，不能凭填写 AppID 获得 |

小游戏 AppID 的查找、创建和预览入口参见官方[开发小游戏](https://developer.open-douyin.com/docs/resource/zh-CN/mini-game/guide/minigame/develop/)。小游戏 IDE 的登录账号须具备对应 AppID 的开发权限；测试号仅支持预览调试，不能上传，参见[小游戏 IDE 概览](https://partner.open-douyin.com/docs/resource/zh-CN/mini-game/develop/dev-tools/mini-app-developer-instrument)。

广告位创建路径按小游戏官方 JavaScript API 文档为「商业化 → 流量主 → 广告管理」。先核对流量主开通状态，再分别创建对应类型的广告位；ID 格式正确不证明广告位有效或有广告填充。参见[激励视频广告接入](https://developer.open-douyin.com/docs/resource/zh-CN/mini-game/develop/api/javascript-api/ads/tt-create-rewarded-video-ad)、[插屏广告接入](https://developer.open-douyin.com/docs/resource/zh-CN/mini-game/develop/api/javascript-api/ads/tt-create-interstitial-ad)。后台菜单以登录后的实际页面为准。

小游戏测试设备入口为「控制台 → 本小游戏详情 → 开发 → 开发设置 → 测试管理 → 添加设备」，使用实际试玩的抖音账号扫码加入。[小游戏测试设备说明](https://developer.open-douyin.com/docs/resource/zh-CN/mini-game/develop/dev-tools/game-debug/bonus-scene)给出上述菜单；[小游戏真机调试说明](https://developer.open-douyin.com/docs/resource/zh-CN/mini-game/develop/dev-tools/game-debug/real-machine-adjust)也将该模块称为“调试管理”，以当前后台标签为准。协作者的设备同样需要测试权限。

若 IDE 点击预览先弹出抖音账号绑定码，先由本人使用试玩账号完成绑定，再生成游戏预览码。手机“开发者模式”入口在「我 → 更多功能」；Android 开启后需重启抖音。预览授权使用上述测试管理入口；不要使用面向关注运营能力的「基础设置 → 抖音号绑定」。加入名单、完成绑定与实际扫码运行应分别记录，不凭绑定成功就记为手机测试通过。

只需在本地填写 AppID 和两种广告位 ID。不要将 AppSecret、验证码、密码、Cookie、登录令牌或结算账户写入项目配置。模板中的空字符串是明确缺项，不是假账号；预检也不会打印完整 ID。

## 2. 生成并预检联调包

在项目根目录打开 PowerShell。以下复制命令仅在配置尚不存在时创建文件，保护已有账号配置：

```powershell
if (!(Test-Path -LiteralPath ./config.local.json)) {
  Copy-Item -LiteralPath ./config.local.example.json -Destination ./config.local.json
}
```

编辑 `config.local.json`，把从该小游戏后台复制的三个 ID 填入相应字段。`allowSimulatedAds`、`analyticsEnabled`、`debug` 在第一轮保持 `false`。该文件已被 Git 忽略。然后执行：

```powershell
npm test
npm run build
node tools/preflight.mjs
node tools/preflight.mjs --strict
```

构建产物目录为 `build/douyin/`。应包含 `game.js`、`game.bundle.js`、`game.json`、`project.config.json`、`config.js` 和 `audio/` 下七个 WAV。每次修改源码或本地配置后都要重新构建。只改生成的 `config.js` 会在下次构建时被覆盖；预检会检查本地与生成配置、IDE AppID 是否一致。

当前最终构建为 1.0.0，12 个必需文件共 192,204 字节（187.7 KiB）。全套 207/207 项测试与静态代码预检通过，两个广告位 ID 仍缺失，严格模式保留未就绪结论。测试证据保存在 [test-results.txt](../artifacts/test-results.txt)；本次文档同步读取已保存的结果，没有重新执行测试。

| 预检输出 | 含义 |
| --- | --- |
| 代码准备通过 | 文件、入口、配置、模拟关闭、WAV 文件头和包体静态检查通过；不是游戏运行测试 |
| 账号配置已填写 | 只通过基本格式与常见占位内容检查；真实归属、启用状态和权限仍需平台核验 |
| 账号配置缺项 | 填写对应 ID 后重建；本地无配置时也能查看具体缺项 |
| 平台 / 真机待实测 | 脚本始终保留该结论，不会因配置非空而变成通过 |

普通模式退出码：`0` 为本地代码准备通过，`1` 为代码 / 配置 / 文件错误。`--strict` 额外在账号配置缺项时返回 `2`。`--json` 输出可归档的脱敏 JSON 报告。即使严格模式返回 `0`，也不证明账号真实有效、广告可展示或平台验收通过。

当前项目不分包；脚本按本地文件总大小检查 20 MiB 上限。官方区分未分包总包 20 MB 与分包后主包 4 MB；IDE 统计和压缩规则不同，最终以实际导入 / 上传结果为准，参见[小游戏代码包](https://developer.open-douyin.com/docs/resource/zh-CN/mini-game/develop/guide/basic-function/subpackages/introduction)。

游戏的广告限制仍生效：启动前 90 秒不开放激励；激励无固定冷却；插屏受启动保护、平台60 秒间隔、激励结束后 60 秒间隔及前 20 分钟最多两次限制。通过正常玩法到达条件；首轮不要改时间、反复请求真实广告来制造测试流量。无填充表示本次没有可展示广告，不等于完整观看。

激励视频播放期间宿主会暂停游戏逻辑，iOS 与 Android 的前后台事件表现可能不同，因此两种系统都需实测。该差异来源于官方[激励视频 API 说明](https://developer.open-douyin.com/docs/resource/zh-CN/mini-game/develop/api/javascript-api/ads/tt-create-rewarded-video-ad)。

## 5. 何时可以进入发布候选版

本步骤完成的证据是：真实小游戏账号及广告位已核对、构建可在 IDE 导入并在手机预览、上述首轮用例有实际结果、阻断问题修复。此时可以推进完整试玩、多机型性能和发布材料准备。

个人账号认证已完成；健康游戏忠告及无奖励侧边栏已实现，并取得上述浏览器与 IDE 实际观察。Android 侧边栏问题原因已确认是未上线游戏平台限制，仅待上线或测试加白后复验，不再作为待排查代码故障。软著尚未办理、自审尚未完成，仍阻碍上线。隐私与其他资质材料、版本提审和发布仍需后续检查；当前联调包不宣称已通过平台验收。官方[开发小游戏](https://developer.open-douyin.com/docs/resource/zh-CN/mini-game/guide/minigame/develop/)明确上线前需要接入必接能力。上传测试通道、提交审核和正式发布应分别记录，不把预览二维码或基础试玩正常当成上线结果。后续按 [发布准备清单](RELEASE_CHECKLIST.md)补证据，技术材料可从 [说明书草稿](copyright/manual-draft.md)继续完善。
