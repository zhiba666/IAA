# 成长任务系统

更新：2026-09-06。已加入浏览器试玩与抖音构建包。

## 为什么加入

现有订单围绕累计产量，适合作为经营收入；成长任务补充“尝试一种操作”的短目标，让玩家自然接触三类升级、免费爆锅和设备换代。任务是可选成长手册，完成后主动领一份金币，不完成也能继续生产、装车与通关。

## 玩家体验

主屏原引导旁常驻“成长任务”，显示当前目标进度或可领奖数量；电脑 Q 打开。面板每章四项，不需要滚动。卡片展示完成条件、进度、金币奖励和具体提示。

- 开工 → 经营 → 扩张 → 竣工，共 4 章、16 项；领取本章全部奖励后解锁下一章。
- 同章任务同时累计，可按任意顺序完成和领取。锁定章节可以预览，已做过的操作照常计入，解锁后追认。
- “去完成”定位升级、订单或设备详情，并高亮相关按钮；不会直接购买、装车、换代或替玩家点击生产。
- 目标完成后显示“领取奖励”，点击即到账并播放反馈。已领取卡片保留记录，重新打开或重启不能重复领取。
- 没有每日刷新、限时奖励、连续登录或看广告任务。首项要求亲手点击 5 次；纯放置可继续正常通关，未参与点击教学时后续任务章节保持锁定。

## 存档与实现

保留 version 1 存档，只新增 claimedQuests 已领 ID 列表。进度来自原有 taps、bursts、升级等级、orderIndex 和 machine，避免另建易失同步的计数器。旧档无需迁移操作，也不自动发奖；任务首次打开时即可查看历史达标状态。

已领列表白名单去重，未知 ID 和存档中的伪造奖励字段不会成为发奖依据。每次领取由核心再次校验章节、达标和已领状态，更新领取记录与金币后立即保存。与原游戏相同，进度属于本地设备，清理本地数据会丢失进度。

- src/core.js：独立 QUEST_CHAPTERS 定义、getView().quests、claimQuest(id)、存档校验。
- src/main.js：任务操作路由、实际领奖、保存、音效及本地 quest 事件。
- src/renderer.js：常驻入口、四章面板、禁用/可领状态、导航高亮与金币反馈。
- tools/experience-check.mjs：只读报告补充任务状态及首次领奖采样，不进入抖音包。

## 数值验证

使用真实核心逻辑，从零金币开始，固定回本策略持续升级和装车；对比同一策略领取任务与不领取任务。结果用于回归，不代表真人操作耗时；模拟没有计入打开任务面板、阅读或点击领奖的时间。

| 策略 | 首次升级（不领取 → 领取） | 完成主线及六机器 | 已领任务 |
| --- | --- | --- | ---: |
| 主动，每秒点击 2 次 | 7 → 4 秒 | 58分40秒 → 58分31秒 | 16 |
| 低频，每秒点击 1 次 | 12 → 6 秒 | 74分59秒 → 74分47秒 | 16 |
| 纯放置，不点击生产 | 61 → 61 秒 | 103分42秒 → 103分41秒 | 3 |

主动/低频全程各加速约 0.3%，没有连续瞬间跨过机器阶段。主动路线累计任务金币 4,204,086,880，低于全主线订单奖励的 10%。原默认模拟仍不领取任务，保留此前回归基线。

## 验收结果

- npm test：260/260 通过（原 232 项 + 任务核心 14 项 + 展示 8 项 + 主程序集成 3 项 + 数值 3 项）。覆盖重复/重载领奖、异常存档、跨章追认、锁章、操作导航、实际金币反馈和全流程可达成。
- npm run build：成功，5 个模块，bundle 102.6 KiB；浏览器与抖音包均包含新系统。
- npm run preflight：代码静态预检通过，抖音总包 206.4 KiB。已有两个广告位空缺不影响普通任务领奖；没有接入新的广告能力。
- 内置浏览器 390×844：已有双缸机存档追认开工章 4 项；逐个领取后显示 4/16、卡片禁用且第二章解锁。
- 内置浏览器独立来源 4181、320×568：零金币/零点击开始，实际点击 5 次；领取 8 金币，任务导航回到升级区，手动花 16 金币升到 Lv.1，再领取 12 金币；第二章预览不能领取。面板全部四卡及页脚可见，未遮挡操作。
- 刷新后保留 2 个已领 ID 和爆裂玉米 Lv.1，两项均显示已领取；只读游戏错误采样为空。
- 浏览器连接工具未提供 Chrome，故使用内置浏览器。QA 父页面工具控制台出现两条 MutationObserver.observe 错误，未提供来源堆栈；本项目源码/QA 页/构建包没有 MutationObserver 调用，游戏错误采样无对应错误，来源尚未确证。普通游戏页控制台 error 记录为空。

本轮不宣称 IDE 或真机验收；真机验收与软著办理继续按用户原指令暂停。历史体验记录保留。
