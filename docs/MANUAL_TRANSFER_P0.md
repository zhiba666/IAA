# 1.5 首段手动转运原型（P0）

范围：用正式入口验证“待装仓 → 装杯进料位”的批量搬运。产品优化方案名称为 1.5，软件版本继续使用 2.0.0；这不是完整 1.5 发布。

## 运行

执行 `npm run build`、`npm start` 后，访问：

- 原有自动生产对照：`http://127.0.0.1:4173/`
- 首段搬运实验：`http://127.0.0.1:4173/?experiment=manual-transfer-p0`

抖音开发环境可在本地配置中显式设置 `"experiment": "manual-transfer-p0"` 后构建；默认不启用。不要为试玩清空已有存档。

实验使用独立键 `little_popcorn_factory_manual_transfer_p0_v3` 和 schema 3，明确标记 `experiment`。正常游戏继续读写 `little_popcorn_factory_pipeline_v2`，旧 `little_popcorn_factory_v1` 不动。P0 不做正式 v2→v3 迁移；实验与正常模式互不加载彼此存档。重新开始仅影响当前模式的键。

## 操作和边界

1. 爆锅自动生产，货物积存在待装仓。第一批最多拿 4 份，此后每批最多 12 份。
2. 按住待装仓或“拿一批”区域，拖到装杯进料区域松手；也可先点源仓、再点进料区域完成同样的搬运。
3. 进料位容量 12 份。按实际空位接收，未接收部分留在源仓；满仓时不能继续放入。
4. 装杯机从进料位取料并真实加工，后面的成品运输和出货继续自动。搬运本身不发金币。
5. 松手到非法位置、移出画面、第二根手指、取消事件、缩放、失焦、打开设置或切后台，均释放预留。拖动后不会误开工位购买。

货物在预留期间仍占源仓容量；保存前释放预留，存档不含悬空货物。普通自动保存会等待当前搬运结束；生命周期保存取消搬运后立即执行。保存失败保留当前运行工厂。

P0 保留原设备升级数值，只改变首段供料。扩建暂不开放，第二段手动搬运和自动化购买尚未实现。无人操作的长期出货基线显示为 0，最近 10 秒实测标注含手动搬运，避免把手工补料误报为自动能力。

## 核验

- `npm test`：原有回归与新增核心守恒、取消/重入、跨模式存档、真实入口操作、布局及预测测试。
- `npm run preflight`：包体与发布配置检查；发布账号或真机未验证的事项仍按实际输出记录。
- Chrome：正式入口实验开关下检查点按、拖拽、加工和真实销售；小屏、安全区和展开面板同时由布局测试覆盖。

后续 P1 才加入第二段手动转运、两段独立自动化及正式存档迁移；P2 再校准前 10 分钟与首次扩建。当前 P0 不据此宣称节奏目标或真机验收已经通过。
