# v1.1 实现与验证记录

2026-09-10 完成实现与验证 · 2026-09-11 整理源码交付，包版本 `1.1.0`。尚未创建 GitHub Release 或发布到抖音平台。

## 实现范围

- 货物仅通过同一连续手势拖拽搬运：8 逻辑像素阈值后预留，A/B 各自对应入口，合法高亮与提交使用同一命中函数。点按货仓、点按入口、依次点按均不搬运。
- 全屏工厂与覆盖层分离；三台机器、两仓、两入口避开安全区与 HUD。打开设备、物流、扩建窗口不会重新排布机器。窗口居中，短屏只滚动内容，关闭与确认位置固定。
- 每次购买绑定对象、目标等级、名称、价格和唯一报价；确认复核，成功关闭并作废。还修复了确认窗关闭后连点旧坐标会误购背后机器的问题：连续点按旧确认区域会被消耗，明确点击其他位置或静默 600ms 后恢复正常操作。
- HUD 显示真实余额和最近 10 秒实际出货。设备预测、采样说明、扩建条件按需查看；实际手动输入的采样证据到期后不再显示“含手动”。试运行停在零且设备能力不足时显示具体原因。
- 教学只在对应路线有真实可用货物且尚未成功时出现；自动化旧档跳过。拿起、拖影、入口提示、落料与回弹不修改库存。存档或美术失败保留查看／重试入口。
- 接入手势、地板延展、墙角三张 PNG，共 87 张正式运行资源。两端资源文件共 1,928,459 B，基础 RGBA 估算 28,400,528 B；构建检查预算与逐文件哈希。

`src/core.js` 和 `src/factory-rules.js` 未改动。继续使用 schema 4、正式 `little_popcorn_factory_automation_v4` 存档键和 `v15` 玩法模式。旧 v2 迁移只有在写入校验成功后才激活；保留自动化、原规格、在制品和备份。后台暂停且不补离线收益。

## Chrome 实际运行证据

[截图与录像索引](../../output/v11-runtime/index.html) · [结构化核验报告](../../output/v11-runtime/report.json)

全部来自正式 Web bundle，通过独立本机验收 origin 加载可校验的测试存档，未读取或覆盖用户正常浏览器游戏 origin 的存档。每份新诊断记录实际运行版本、bundle SHA、资源加载结果和守恒库存。PNG 是 Canvas 的原始导出，未重绘。

代表性人工检查覆盖 320×524 首代／第六代、360×640 半自动、390×844 全自动、430×932 第六代，以及居中设备／物流／扩建窗和 24px 上下安全区。完整组合是否有 Chrome 截图，以报告覆盖矩阵为准；没有截图的组合不冒充人工观察通过。

首次链路证据：依次点按后 A/B 成功次数均为 0；连续拖拽 A 实际送入 4 份，装杯后出现 4 份待发；连续拖拽 B 实际送入 4 份，只有出货机加工完成后余额与累计售出变为 4。两段鼠标拖拽分别保存 8 秒录屏；诊断计数证明状态链，点按动作的因果由本次操作记录及自动输入回归补充。

430px 故障场景通过验收页 `fail=1` 明确注入一次机器图片 503。第一份诊断为 86 张加载、1 张失败；操作设置中的“重新加载美术”后恢复为 87 张加载、0 失败，金币和机器操作仍保留。

验收页可暂停并用“推进 0.5 秒”驱动原 bundle 的时间输入。使用该功能完成加工及弹窗淡入后的截图，避免 Chrome 后台页节流影响观察；没有直接调用 Game 购买／投料，也没有改写正式 bundle。此类 QA 时钟与后台帧率不能当作正常运行帧率、真人完成时间或真机性能。
