# 软著技术材料草稿

这些材料用于核对《小小爆米花厂》1.0.0的真实功能和程序内容。文档封面和页脚标为“内部草稿 / 待权利人确认”，没有填写人名、虚构开发日期、登记号码、签名或法定声明。

## 本次范围

操作说明书覆盖运行环境、启动与健康游戏忠告、主界面、生产、爆锅、三项升级、六阶段设备、订单、激励、离线收益、保存、设置和侧边栏。配图通过当前`Renderer.draw`直接渲染固定示例状态；包含抖音样式的图仅展示代码分支，未调用平台API，不是浏览器/Android截图或真机验证证据。图片字体的650/750等字重在本地绘图库中归整为相邻100级，绕开该库误解析字号的问题；游戏源码没有为配图修改。

程序材料按文件清单纳入全部5个`src`文件，加必要的构建、音效生成、本地预览脚本和HTML入口。不重复纳入生成bundle、测试、第三方库或本地配置。源文件以原始字节保存，提供逐文件SHA-256和PDF页码映射。长行只在展示时折行，续排标记在行号栏，拼回各段可还原原始文本（制表符仅作4空格显示）。原有空行保留，未插入空代码凑页。

## 官方排版依据与草稿边界

2026-09-05核验的北京市版权局办事页面明确：鉴别材料分程序和文档；不足60页时提供全部，达到相应长度时提交连续前后各30页；除特定情况外，程序每页至少50行、文档每页至少30行。材料用A4纵向，名称和版本须与申请表一致，页码置于右上方。依据：[计算机软件著作权登记初审](https://banshi.beijing.gov.cn/pubtask/task/1/110000000000/3e283672-76be-4c8c-98e8-0bebe9bd06bf_app.html)。该页引用《计算机软件著作权登记办法》第十条、第十七条和中国版权保护中心登记指南。

本次程序PDF采用50排版行/页，末页据实保留；由于原代码存在较长源行和空行，排版行数不等于非空逻辑代码行数。申请人应在提交前向实际受理端确认这种折行方案；若要求重新整理源码版式，应从随附完整源文件生成，不能加重复代码凑页。说明书封面、最后一页正文及图示页不足30文字行，作为内部审阅草稿保留，正式材料对末页及图页的处理同样须按受理端要求核对。本次不把这些草稿宣称为可直接通过登记的正式申请材料。

文档样式采用compact_reference_guide，具名覆盖为A4登记纸型、中文宋体/英文Calibri、全黑正文，以及正文11pt、1.25倍行距、段后4pt的登记密度；采用简洁技术封面，正文使用真实Word标题样式和右上页码，不使用手工拼接标题或版面表格。

## 待本人核对的申请事实

- 著作权人真实姓名及身份证明；合作、委托或其他开发关系的真实证明资料。
- 拟登记的软件全称、简称、版本写法，以及各处界面与申请表的一致性。
- 开发完成日期、首次发表状态和日期、开发方式、权利取得和归属，均以真实记录为依据。
- 正式申请表、身份证件、签字或其他声明由申请人亲自核对办理，不由本草稿代填代签。
- 真实广告未开通；Android基础体验正常是用户反馈，不等于全机型或广告链路完成验证。

## 复现

运行时先调用Codex的`load_workspace_dependencies`定位本机Python、Node、Node包和Poppler。请使用返回的运行时，不在项目安装依赖。

1. 在源码停止改动后执行`generate-copyright-screenshots.mjs`，并将`CODEX_ARTIFACT_NODE_MODULES`设为返回的Node包目录。
2. 执行`generate-copyright.py --frozen --screenshots docs/copyright/screenshots.json`生成DOCX、程序PDF、源快照和映射。仅更新手册时用`--manual-only`，不重抓代码。
3. 标准`render_docx.py`在本机因缺少soffice无法运行。本次通过独立隐藏Word实例执行`generate-copyright-word-pdf.ps1 -InputDocx <生成的DOCX>`，从同一DOCX实际导出PDF；不连接或关闭用户已有Word文档。
4. 执行`generate-copyright-qa.py`使用Poppler渲染每个PDF页面，并检查A4页面、文字边界、DOCX结构和源哈希；随后查看全部说明书页及程序页概览/文字细节。

所有正式交付草稿位于`deliverables/copyright/`。本目录中的渲染图、QA、配图和生成内容源用于复现，不属于登记机构已认可的材料或已受理证明。
