# 当前开发重心

更新：2026-09-08。当前版本：2.0.0，轻经营生产线重构。

## 已完成的核心替换

正式浏览器和抖音入口均使用「爆锅 → 装杯 → 出货」三环节生产模拟。每个工位按独立加工周期、批次和并行通道处理真实库存；仓位满时保留完成的在制品并阻塞上游，缺料则等待。渲染只读模拟快照，不创建产量或结算金币，也不再通过安装器覆盖旧方法。

玩家观察积压和实际速度，点击相应工位购买升级，再赚钱扩建。初始能力 4／2／6 份每秒；第一次装杯改造花费 30 金币，提升到 6 份每秒，随后瓶颈移到爆锅。画面同时区分设备能力和最近 10 秒实际吞吐量。六代机器保留，价格、库存上限、独立工位改造与固定扩建条件集中在 `src/factory-rules.js`；后期成长包括真实并行通道、双份加工和成组/成箱出货。

唯一逻辑单位是份，唯一货币是金币，只有最终出货结算。累计投产包含爆锅在制品，满足「投产 = 售出 + 两仓库存 + 三工位在制品」；金币满足「余额 = 售出收入 − 改造和扩建支出」。没有重复包装计产。

主界面展示全生产线、金币和一个扩建目标。首次提示附着在装杯工位，改造后短暂提示观察改善，不建立说明弹窗队列。进入立即自动开工，不要求点击生产。

## 已断开的旧系统

旧合同、60%/40%分账、三次添料限制、能量奖励、设备图鉴、品牌、广告入口和离线奖励均已退出正式依赖及后台结算。旧引导、设备和离线模块及 QA 演示页已移除；历史数值分析脚本停止运行。广告适配保留明确返回不可用的接口，不创建 SDK 实例。

新存档键为 `little_popcorn_factory_pipeline_v2`，版本为 2。首次非阻塞说明从新工厂开始；不读取、迁移或删除 `little_popcorn_factory_v1`。后台暂停，重载不按时间差补产；没有收到生命周期事件的超过 1 秒前台冻结帧也视为暂停。小于等于 1 秒的有效帧时长全部由同一核心时钟处理。

原生 Canvas、程序化美术、WebAudio、抖音包内 WAV、触摸/安全区/存储/生命周期/侧边栏适配继续保留。既有未提交调研文档未修改。

## 本轮技术检查

运行方式与规则表见 [README](../README.md)。不进行用户访谈、A/B 测试或等待玩家验证。

- **核心生产**：整数份与金币守恒、初始积压到满仓、下游等待、首次装杯升级后恢复、后期两个仓位均满时的批处理堵塞与出货改造恢复。
- **购买与成长**：独立工位扣款、失败不扣款、禁止隐形旧输入、已有批次沿用剩余加工时间、新并行通道加入而不重复计产、六代固定目标可自然达到。
- **存档与时间**：保存和重载在制品、120Hz 时间量子零头与实际速度窗口，任意离开时间不补钱；多个时间步长在初期及后期批量加工得到相同库存、金币和加工状态。
- **主入口与布局**：真实入口自动运转、首次改造和面板作用范围、自动保存失败恢复、只重开 v2 工厂、后台和冻结恢复、六代只读渲染、320×524/390×844 及抖音状态栏/胶囊安全区。
- **平台与产物**：浏览器输入、失去触摸捕获、原生触摸取消、存储隔离、生命周期、侧边栏、声音关闭/复用/无 API 降级，四类非 DOM 抖音宿主执行正式生成入口。

已执行 `npm test`：**124/124 通过，0 失败、0 跳过**。`npm run build:dev`、`npm run build`、`npm run preflight`、`npm run preflight:strict` 均通过；最终保留 release 构建（8 个模块，bundle 约 77.7 KiB）。`npm test` 现在先构建当前源码再执行整包测试，避免测试旧产物。两个构建模式都禁用连点与广告模拟，广告位不再是严格预检要求。

额外用正式核心自然经营至六代，并逐阶段渲染核对真实并行通道和批量包装；图像输出位于本地 `artifacts/pipeline-review/`，不是独立演示页。此检查发现并修复了部分 Canvas 对非整百字重的兼容问题。`git diff --check` 通过。

Chrome 正式入口已检查 390×844 和 320×524：升级前待装库存为 12/12 份、实际出货 2 份/秒；购买装杯改造后库存下降，稳定到 4 份/秒，装杯设备能力仍清楚显示 6 份/秒。重载后改造和库存状态保留。截图/浏览器结果与下列脚本推演均不代表真机验收或玩家体验结论。

固定购买顺序的核心技术模拟，在约 95／335／800／1575／2650 秒到达第 2～6 代，最终可达 96 份/秒真实吞吐；这是可达性证据，不是对玩家通关时长、留存或收益的预测。
