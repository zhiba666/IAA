首页“升级 / 订单 / 任务 / 工厂”各自进入独立面板；品牌合作、涡轮增压、蓝图与经营记录归入工厂。目标卡会提示普通领单，广告不进入高频生产触控区域。禁用点火按钮也会拦截触摸，避免穿透后意外生产。

生产粒子上限为 180；自动生产事件合并后生成视觉反馈，避免高帧率下漏掉连续出料或无限堆积粒子。换代动画持续约 1.8 秒且不锁住玩家操作。浏览器增强程序合成音效；抖音端继续使用既有包内 WAV，不能将浏览器听感等同于真机验证。

## 可选“完美爆锅”规则

- 首次免费爆锅仍按既有方式自动触发，之后出现点火按钮。
- 能量达到 80 后可尝试，每锅一次；能量在 **92–98（含边界）** 时点火成功。
- 成功后下一次正常免费爆锅额外生产 **20%**，按正常价格自动售出。按钮显示已获得的本锅加成。
- 过早、过晚或完全不参与，都不扣金币、不减产、不延迟原有自动爆锅。
- 本锅尝试与加成为临时状态，不写入存档；离开游戏并恢复后取消。重复点击不能叠加，下一锅重新开放。
- 记录合法尝试的成功与失败，后续可分析参与比例和命中情况。当前窗口与 20% 加成是待试玩验证的原型参数。

免费生产、原有爆锅公式、升级成本、任务金币与广告倍数保持原值；只有主动点火成功的那一锅增加上述可选奖励。品牌合作仍为每级永久 +20%、最高 +200%；五类激励之间仍无 120 秒冷却，保留播放互斥。

## 下一轮开发依据

1. 对新玩家做不提示操作的首局试玩，分别观察目标是否看懂、首次升级前的停顿、首单是否主动普通领取；与旧版在相同条件下比较。
2. 对比点火的参与和成功情况，确认是否增加乐趣、是否分散升级注意力。依据记录再调整窗口与提示，不先加惩罚或更多玩法系统。
3. 收集普通路线的订单等待与首次换代记录，再决定是否调整中段经济。当前不以人工自动化操作的用时推断留存、广告收益或人类通关速度。

真机验收与软著办理按用户既有要求继续暂停。本轮没有发布，也没有配置真实广告位；浏览器模拟结果不能作为真实广告填充、收益或手机性能证据。

## 复现

```powershell
npm run build
node tools/experience-check.mjs
npm test
npm run preflight
npm start
```

打开 `/experience-check.html?mode=normal&width=390&height=844` 或 `/experience-check.html?mode=low&width=320&height=568`，在左侧游戏操作，右侧只读观察并手动导出。旧存档会作为基线保留；不清空用户已有进度来制造首局结果。`preflight:strict` 中缺失广告位仍是发布准备事项。
