## 1. 验收环境与执行入口

- 在项目目录执行 `npm run build`，确认浏览器产物与抖音小游戏包能够生成。
- 执行 `npm test`，保留通过/失败数量；核心数值有变动后必须重跑相关用例和成长模拟。
- 执行 `node tests/balance.cjs`，输出当前完整配置、四条路线逐单/逐机器时刻、设备资金缺口、广告报价与到账、观看后升级及离线结算；该脚本使用固定决策策略，不是真实用户留存或广告收益测试。
- 执行 `npm start`，按终端实际地址打开浏览器版本；测试前记录是否使用新存档。
- 在根目录 `config.local.json` 填写本项目 AppID 和广告位 ID 后执行构建，再使用抖音开发者工具导入 `build/douyin/`。本地配置不进入版本控制，抖音构建强制关闭模拟广告；不得填入无归属的其他项目 ID。
- 真机记录：设备型号、系统、抖音版本、小游戏基础库/开发工具版本、包版本、广告配置、操作路线和异常日志。
- 手机测试权限使用小游戏后台「开发 → 开发设置 → 测试管理 → 添加设备」，由实际试玩抖音号扫码加入；官方[小游戏测试设备说明](https://developer.open-douyin.com/docs/resource/zh-CN/mini-game/develop/dev-tools/game-debug/bonus-scene)。

## 5. 成长节奏的四条路线

模拟使用核心规则，人工试玩使用完整 UI；两者记录分开。模拟策略必须写清点击频率、升级购买优先级、机器购买优先级、订单领取时机以及广告使用规则，否则用时不可比较。

| 路线 | 固定输入 | 必记结果 | 通过标准 |
| --- | --- | --- | --- |
| 主动零广告 | 建议基线每秒 2 次点击；不请求广告 | 首次升级/爆锅；6 机器时刻；20 订单时刻；主线总时长 | 完整通关，无死锁和强制广告 |
| 主动高广告 | 同点击频率，按合法冷却选择奖励 | 同上，加各广告发起/完成/奖励和观看后升级 | 同输入下明显加速；没有叠乘漏洞 |
| 纯挂机 | 从新档不主动点击，订单/购买按明确策略自动执行 | 首次可买、各阶段与主线时长 | 原始自动产能确保推进，无永久卡死 |
| 离线回归 | 固定永久产能；离线 2 小时及超上限时长 | 实际计入时长、金币、产量、一次领取状态 | 数值符合上限/折损，重启不重复发奖 |
