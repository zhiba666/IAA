# 增量游戏 UI 与玩法设计调研：对《小小爆米花厂》的参考价值

调研日期：2026-09-06。目标：找出有一手证据、可以转化为设计决策的参考，并对应当前项目的下一轮体验打磨。

最值得采用的组合是：Egg, Inc. 的场景成长表现、AdVenture Capitalist 的自动化回报、Idle Miner Tycoon 的投资判断、Gnorp 的行为型升级、Universal Paperclips 的阶段变化，以及 Melvor Idle 的回归摘要。Antimatter Dimensions、Kittens Game、Revolution Idle 适合研究长线结构，移植优先级低于前六项。

本文的案例事实来自开发者官网、官方商店、开发日志、帮助文档和官方源码。带“建议”“候选”“判断”的内容是针对本项目的设计推导，不代表竞品原样存在这些方案，也不代表已验证的留存、广告收益或通关数据。

**UI 的核心：让玩家读懂因果**

一个有效的增量游戏主屏，至少应让玩家回答四件事：我现在拥有多少；系统现在怎样生产；当前还差什么；下一次投入会改变什么。这个四问框架是本次调研归纳，不是某一款游戏的官方设计规范。

Egg, Inc. 的官方截图提供了一个很直接的空间分工：场景中看到农场和鸡群，研究面板中比较升级。由此推导到本项目，主场景不应只是升级列表旁的装饰，而要能表达点击产量、自动频率、爆锅规模和机器阶段。管理面板则保留精确单位与比较，不要求玩家从粒子数量反推收益。

Universal Paperclips 的初始页面另一个启发是内容展开的节制。本次 Chrome 初始界面只看到较少的经营与生产模块；网页文本抽取却能读到后期系统。后者不能用来断言新手实际看见所有内容。这也说明 UI 调研需要区分网页中存在的内容与当前可见内容。

NN/g 对渐进披露的建议是先提供主要功能，再按需提供次要功能，同时让入口和标签易于理解。本项目可以借此检查面板负担，但不应把频繁使用的操作藏得更深。[NN/g：Progressive Disclosure](https://www.nngroup.com/articles/progressive-disclosure/)

| UI 部位 | 对当前项目的建议 | 应当避免的结果 |
| --- | --- | --- |
| 顶部资产 | 金币和自动金币/秒继续相邻；有临时增压时，让当前收入与常驻收入的关系可查 | 一个醒目的倍率，却不说明作用于哪些收入 |
| 当前目标 | 保留一个主目标；需要领单时显示装车，需要攒钱时显示缺口 | 顶部目标、下部推荐、任务红点同时给出不同优先级 |
| 生产场景 | 用机器动作、出料频率、包装和爆锅规模表达成长；大阶段有明显轮廓变化 | 所有升级都只增加浮字与闪光，机器本体没有变化 |
| 升级卡 | 当前效果→购买后效果、价格、真实单位；三线允许自由比较 | 把点击收益、每秒产量和售价都标成同一种“效率” |
| 订单 | 保留本单进度与明确奖励；装车表达完成里程碑 | 把累计生产订单包装成实际扣库存交易 |
| 换代 | 展示下一代的形态、条件、常驻收益；若新增能力，放在倍率之前说明 | 用巨大倍率掩盖六代机器操作完全相同 |
| 火候 | 保留当前位置、最佳区间、结果文字；无需一直盯着屏幕也能正常经营 | 只靠颜色区别状态，或把可选操作变成必须连点 |
| 回归 | 收益摘要→可做的一次投资→生产现场 | 领完钱后还要重新翻四个面板才知道该做什么 |
| 激励广告 | 标注视频、收益范围、持续或永久、当前→观看后 | “再加20%”与“最终产量再乘1.2”混用 |

当前源码已经具备目标卡、推荐卡、三线升级预览、机器前后对照和固定主交互位置。UI 的下一步应是检验这些信息是否帮助理解，而不是再添加同类提示。实现依据见 [interface.js](C:/Users/chenweilun/Documents/GitHub/IAA/src/interface.js:11)、next-step.js（当时路径：`src/next-step.js:53`，文件已删除）。

**一个具体的小屏问题：机器画面还有多少空间**

按当前首页布局公式推算，320×568 时生产场景容器高约152像素，扣除44像素场景标题区，传入机器场景绘制的高度约108像素；390×844 时对应约412和368像素。这是源码静态推算，不是本次截图测量，也不证明玩家已经看不清。[布局公式](C:/Users/chenweilun/Documents/GitHub/IAA/src/interface.js:38)

这意味着同一套“场景表现成长”的设计，在小屏可能表现得很弱。值得制作一个小屏候选布局：将62像素目标卡与69像素推荐卡的信息合并到一张行动卡，避免同一件事在两个位置重复说明，把释放的高度交给机器。需要仍然保留目标、收益/缺口、主操作，并保持生产和点火按钮在各状态下稳定。只在视口布局模式切换，不随每次目标变化上下跳动。

这里的取舍不是简单增加可视面积：还要验证合并后是否损失目标说明，以及频繁查看升级是否更费操作。正常屏可以保留当前分区，小屏方案不必强迫所有设备使用。

**画面风格与反馈可以怎样借鉴**

当前代码的浅奶油色底、深绿色文字与操作、黄色奖励、六代机器差异，已经形成可继续打磨的方向。[当前色彩定义](C:/Users/chenweilun/Documents/GitHub/IAA/src/interface.js:7)

建议延续“食品温暖感＋设备成长”的识别：机器轮廓和爆米花实体最先被看到，普通操作用稳定主色，阶段达成用较强对比。黄色目前同时用于火候与广告，这不必立即换色，但应通过图标、文字和位置明确区分，避免玩家仅凭色块猜按钮作用。

信息排版方面，关键资源金额保持固定位置与对齐；长数字使用稳定缩写，详情保留精确说明。低频统计放经营记录，不挤入首屏。按钮中的条件文字需要在买不起、可购买、满级、奖励不可用时都清晰，不能把解释只放在桌面 hover 中。

| 事件 | 建议反馈层级 | 对现有实现的处理 |
| --- | --- | --- |
| 一次点击 | 局部粒子、声音和少量金额变化 | 继续合并快速连点浮字，避免满屏文字 |
| 一次普通升级 | 卡片等级变化、收益更新、对应机器动作变化 | 在已有数值预览之上，强化“改的是哪个部位” |
| 免费爆锅 | 明显的出料峰值与本锅真实收益 | 既有爆锅与完美点火反馈保留，不再叠加全屏弹窗 |
| 普通订单 | 一次装车与大额入账 | 保留及时回到生产的路径 |
| 机器换代 | 前后轮廓、运转方式和声音的显著变化 | 用新能力说明补足“只是变大”的风险 |
| 每次回归 | 一张成果摘要 | 避免连续出现多个独立领奖弹窗 |

视觉粒子应当表达规模和变化趋势，精确结算仍以数值为准。后期可以用成组出料、带速或连续流动表达量级，不必为每份产量绘制一粒实体。现有粒子上限与程序绘制适合继续复用。

**玩法的核心：成长后，玩家会做什么不同的事**

当前循环是点击/自动生产立即出售→三线永久升级→累计产量订单→手动领取额外奖励→金币与已领订单数共同解锁换代。六台机器主要改变产量、售价、外观及品牌容量；从第一口锅起就有自动生产。换代保留升级和累计产量，并不属于清空重来的 prestige。[生产公式](C:/Users/chenweilun/Documents/GitHub/IAA/src/core.js:177)、[换代](C:/Users/chenweilun/Documents/GitHub/IAA/src/core.js:240)

因此，项目当前最值得补的是阶段之间的决策变化。这里有三个层次：提高倍率，让玩家更强；减少重复操作，让玩家更省事；改变选项的相对价值，让玩家重新思考。前两层有助于爽感，第三层决定中后期是否还有可探索的玩法。

Gnorp 的2023年开发日志是一个具体案例：开发者为运输单位设计传送与时间跳跃联动，讨论运输距离价值和跨单位配合，同时用缓慢上浮表达传送进度，避免靠剧烈抖动提示进度。它展示了玩法、动画与信息表达怎样共同设计。[升级设计日志](https://gnorp.dev/news/3-Implementing-An-Upgrade/)

这里借鉴的是设计方法。该日志的部分规则后来有变化，例如后续 beta 记录过传送目标选择调整，不能把2023年细节全部当成当前版本规则。[后续 beta 说明](https://gnorp.dev/beta-update-notes/)

对爆米花厂，可以用一句话筛选升级候选：“买完以后，玩家原来的做法会发生什么变化？”如果答案永远是继续点同一个按钮，只是数字大一点，那么新增内容主要增加了长度，还没有增加新的决策。

**最适合先做原型的玩法：赶单与赚金币的取舍**

本项目天然存在两个目标：订单看产量，机器换代还看金币。售价升级不会直接增加订单产量。利用已有的这两个指标，可以在中期机器试一个轻量经营档位，而不必先造库存、工人和多货币。

以下是示意数值，不是平衡结论；假设不计点击、爆锅、广告和其他增益：

| 经营档位候选 | 产量 | 单价 | 每秒收入 | 在什么目标下有意义 |
| --- | --- | --- | --- | --- |
| 赶单档 | 120份/秒 | 0.90金币/份 | 108金币/秒 | 订单产量未达标，资金已足够或接近足够 |
| 高价档 | 80份/秒 | 1.50金币/份 | 120金币/秒 | 订单条件已满足，正在攒换代金币 |

玩家要判断现在更缺订单进度还是资金。这种取舍直接复用现有金币、产量和目标体系，也让“推荐”有机会解释原因。档位属于一个有待验证的新机制，不能先预设它一定更好；如果玩家只是每次机械地按推荐切换，策略价值仍然有限。

原型应先只在一代机器提供两个易懂选项，展示实际“份/秒”和“金币/秒”，观察理解成本与选择差异。不要同时引入多种配方材料、库存质量、订单失败和员工养成。新机制也不应让旧存档永久失去已经取得的成长。

**六阶段机器的职责候选**

下面是一套分配玩法职责的讨论稿，不是六个全部必须开发的功能。先挑一个阶段原型，成立后再决定是否扩展。

| 阶段 | 现在的基础 | 候选的体验职责 | 复杂度控制 |
| --- | --- | --- | --- |
| 手摇锅 | 点击＋开局自动生产 | 学会生产、领单、升级，看到第一次爆锅 | 继续复用现有引导，不新增管理页 |
| 电热锅 | 更高产量与售价 | 更直观地呈现持续生产与首次自动火力升级的价值 | 保留开局已有的自动收益，不将它移除后重新售卖 |
| 双缸机 | 进一步倍率成长 | 首次尝试赶单/高价的二选一 | 不添加新货币，用真实单位比较 |
| 多头机 | 多头出料表现 | 尝试一个行为型里程碑，让爆锅与生产有新配合 | 先验证一种联动，避免连环倍率组合 |
| 自动流水线 | 更强的自动化视觉 | 减少已经熟练的批量升级或领奖操作 | 自动领单会影响阶段反馈和广告机会，需单独验证后再决定 |
| 巨型爆米花塔 | 最终机器与竣工 | 清楚交付完成感，再提供自选纪录目标 | 不用强制重置打断已经完成的成果 |

自动化的参考价值在于逐步接管旧劳动。Antimatter Dimensions 的官方帮助源码把挑战、自动购买与里程碑保留放在成长体系中；Revolution Idle 则进一步提供宏配置。对当前项目，先研究减少哪一个重复操作就够了，宏编辑器可以留在长期研究中。[Antimatter Dimensions 帮助源码](https://github.com/IvarK/AntimatterDimensionsSourceCode/blob/master/src/core/secret-formula/h2p.js)、[Revolution Idle 官方介绍](https://store.steampowered.com/app/2763740/Revolution_Idle/)

**升级里程碑、批量购买与订单变化**

当前三线升级各24级，单次购买，缺少等级门槛带来的新效果。[升级配置与购买](C:/Users/chenweilun/Documents/GitHub/IAA/src/core.js:4)

可以借传统增量游戏的阶段性倍率思路，在8/16/24级之类与现有上限相容的节点研究里程碑。这些等级是候选，不是行业标准。优先设计可以看懂的差异，例如改变一次爆锅的行为或减少一种操作；如果只是再加一组全局倍率，就必须重新测量内容被压缩了多少。

Kongregate 的增量数值文章讨论指数成本、产能增长和里程碑倍率如何共同形成快慢交替。这是设计工具，不是可以直接套用的节奏处方。[Anthony Pecorella：The Math of Idle Games, Part I](https://www.gamedeveloper.com/design/the-math-of-idle-games-part-i)

批量购买也要看实际需求。24级上限的游戏不必直接使用x10/x100/MAX整排按钮；先观察一段连续升级是否真的需要太多点击。若做“买到下一里程碑”或“可买最大值”，要明确价格与购买后效果，并考虑临近换代时保留设备资金，不能破坏现有推荐的资金保护逻辑。

订单变化优先复用现有4章16项成长任务。主线订单保持累计产量语义，侧面的任务可以引导一次完美点火、某类升级或某项新能力。不要同时把主线订单改成材料扣除、限时失败和指定库存，这会让原本易懂的流程变成另一种经营游戏。

**数值分析应该围绕下一目标，而非只看倍率**

最常见的局部比较是升级价格除以新增每秒收入，但它只在收入来源可比、且忽略后续购买和里程碑时有意义。当前项目已经使用更贴近目标的方式，比较升级前后靠永久自动收入攒够机器资金的时间。[推荐估算说明](GOAL_RECOMMENDATION.md)

若目标还缺D金币，当前每秒收入R，某升级花费C、增加收入ΔR，则局部估算为：不购买需D/R；购买后需(D+C)/(R+ΔR)。后者更短，才说明这次购买在该简化模型下更有利。这个模型不含点击、免费爆锅、临时增压、未领奖励和未来连续购买，因此不应显示为承诺倒计时。

点击升级在本项目中也不是单纯“手指点一下多几份”：它增加基础点击产量，而该值还参与每次免费爆锅产量；点击又增加能量。因此主动玩家与纯挂机玩家的升级价值可能不同。后续调参应至少分开观察主动、低频与回归型行为，不要把统一推荐等同于全局最优。[能量与爆锅](C:/Users/chenweilun/Documents/GitHub/IAA/src/core.js:195)

有一个值得重点记录的压力点：第10单累计目标80万，第11单720万，目标数是9倍跳跃。这不能单独证明卡关，因为同时有新机器、升级与奖励。需要看玩家到这里时的实际产能、未领奖励、升级顺序和等待时长。[订单表](C:/Users/chenweilun/Documents/GitHub/IAA/src/core.js:33)

建议先记录每单完成时间和两单之间的无有效操作时间，再观察换代前后“份/秒”“金币/秒”与下一目标缺口。若出现明显长等待，优先判断是信息不清、购买选择失误、倍率衔接还是内容真的不足，再决定改文案、推荐或经济。

**离线回归：把一笔钱连接到一次决定**

当前离线使用永久自动产能的50%，上限8小时，领取时增加产量与金币；翻倍奖励额外增加金币，不是所有离线产量都翻倍。临时涡轮不参与离线基础计算。[离线生成](C:/Users/chenweilun/Documents/GitHub/IAA/src/core.js:158)、[离线领取](C:/Users/chenweilun/Documents/GitHub/IAA/src/core.js:391)

当前面板已经显示时长、金币与规则。更有价值的增量是告诉玩家：这段收益推动了哪个订单、领取后可以买什么、距下一台机器还差什么。借鉴 Melvor 的成果摘要，并针对本项目增加下一步经营桥接；这部分桥接是本文建议，不是声称竞品已有完全相同的文案。

一个候选结算顺序是：离开时长与有效结算时长→实际新增产量/金币→当前订单是否达标→领取后的一项可执行动作。可以在领取完成后让原有推荐立即接续，不必增加一层“恭喜又可升级”的新弹窗。

因为20单流程有限，离线上限与效率应根据剩余内容测试。不能拿长期游戏的离线上限来直接延长，也不能因为本地脚本约小时级完成就断言真实玩家一小时通关。回归时应当有可兑现的进展，同时仍然让重要换代和竣工被玩家看到。

**广告 UI：高强度也需要可比较的回报**

本项目原始需求接受高广告强度。此次调研建议集中在怎样明确收益和接回经营，不将产品重新定义为低广告游戏。[既有商业化需求](../GAME_DESIGN_HANDOFF.md)

AdVenture Capitalist 的当前官方 FAQ 明确说明存在间歇插屏，并列出双倍增益、离线翻倍、Time Warp 等激励入口。因此不能把它描述成“只有自愿广告”的案例。[官方广告 FAQ](https://screenzilla.helpshift.com/hc/en/5-adventure-capitalist/faq/544-pop-up-ads/)

| 当前广告点 | 玩家应理解的价值 | 值得强化的展示 |
| --- | --- | --- |
| 涡轮增压 | 在线自动生产3倍、90秒 | 明确作用对象与剩余时间；不要让人以为所有点击和爆锅也3倍 |
| 订单加价 | 已有普通奖励，总额变3倍 | 普通奖励、额外奖励、最终总额分清 |
| 设备赞助 | 补充换代资金 | 观看后还差多少；若还缺订单，同屏说明 |
| 离线翻倍 | 离线金币增加 | 明确金币翻倍，不写成订单产量也翻倍 |
| 品牌合作 | 按等级累计永久产量加成 | 累计加成前后、实际产量前后、当前容量条件 |

以上广告规则来自当前源码，具体收益预览已有实现；改进重点是检查实际理解，避免再建一套重复报价面板。[奖励实现](C:/Users/chenweilun/Documents/GitHub/IAA/src/core.js:275)、[广告交互](C:/Users/chenweilun/Documents/GitHub/IAA/src/main.js:87)

品牌的加法叠加尤其值得解释。以未计品牌时产量100份/秒为示意：品牌累计+100%时为200，下一等级累计+120%时为220，实际相对增长10%，并不是当前200再乘1.2。建议采用“品牌加成+100%→+120%；永久产量200→220份/秒”的比较。数值来自现有每级增加20个百分点的规则，示例基准100并非玩家实测存档。[品牌与生产公式](C:/Users/chenweilun/Documents/GitHub/IAA/src/core.js:177)

广告价值还应观察兑现后的经营行为：玩家是否完成了升级、领单或换代，是否很快又停在相同位置。现有曝光、请求、完成、发奖、广告后经营记录可复用；广告完成率本身不能证明玩法满意度，也不是广告造成的净收益。

**为什么暂不把 prestige 列为本轮必做**

Prestige 通常用重置换来长期加成，帮助玩家更快越过旧阶段。Anthony Pecorella 的文章讨论了不同累计口径如何影响重置选择，并强调模型需要迭代，不能视作精确玩家模拟。[The Math of Idle Games, Part III](https://www.kongregate.com/en/pages/the-math-of-idle-games-part-iii)

若未来加入扩厂重生，需要回答：清除哪些内容、保留哪些内容、本轮能获得什么新能力、重新到达旧阶段要多久、重来之后还有什么新决定。只有倍率而重复相同点击，很容易把结局延长成重复劳动。

当前1.0明确把扩厂重生放在后续版本。有限篇幅也能成为增量游戏的合理目标：Universal Paperclips 的作者将作品描述为约4–6小时的体验，这只是作者对作品篇幅的描述，并非平均通关统计。[作者作品页](https://www.franklantz.net/work)

对爆米花厂，先让六阶段20订单中的进展更有差别，完善竣工后的成果展示，再决定循环订单需要怎样的长期层。不要先用重置掩盖现有中后期内容单一。

**建议优先级与可验收结果**

P0表示优先研究或制作小原型，P1表示在P0观察后选择，P2表示后续版本。以下是设计建议，不是已开始的开发任务。

| 优先级 | 候选项 | 为什么值得做 | 判断是否有效 |
| --- | --- | --- | --- |
| P0 | 小屏目标与推荐信息合并方案 | 直接给主机器增加可用空间，减少重复信息 | 玩家仍能解释目标；无需缩小按钮；机器变化更容易辨认 |
| P0 | 离线成果连接下一步升级/订单 | 利用现有系统补上回流接续 | 领完钱后能迅速指出下一步，并找到入口 |
| P0 | 三线升级与品牌累计加成的理解测试 | 界面已展示数值，但尚缺理解证据 | 玩家能分清份/次、份/秒、金币/份和加成百分点 |
| P0 | 双缸机的赶单/高价二选一原型 | 用现有两种目标增加一个真实决策 | 两个档位在不同状态下各有价值；玩家说得出理由 |
| P1 | 一个行为型升级里程碑 | 验证换代或升级能否改变玩法 | 购买前后存在可描述的行为变化，不只是倍率 |
| P1 | 批量升级或部分自动领奖 | 减少已熟练的重复操作 | 操作次数下降，重要成果和广告价值仍可理解 |
| P1 | 第10→11单与换代衔接曲线 | 排查具体数值压力点 | 区分信息卡点、策略问题和实际等待过长 |
| P2 | 简单扩厂重生或研究选择 | 为完整主线之后提供不同目标 | 明确保留项、新能力和回到旧阶段的体验 |
| P2 | 库存物流、多厂、多资源、宏 | 学习完整生产链与策略自动化 | 只有现有体验需要时再扩大系统规模 |

一次有用的观察可以让新玩家分别解释：当前目标是什么、三条升级有什么不同、为什么暂时攒钱、品牌下一次实际加多少、离线回来该做什么。然后观察首次升级、首次爆锅、首次领单和首次换代之间的停顿。问题数量和观察时长按测试条件安排，不把它们当成行业达标线。

玩法原型还应比较不同合理选择，而非只跑一条最优脚本。主动玩家、低频玩家、回归玩家可能需要不同投资顺序。新增选择若始终被同一个选项压倒，应当调整其用途或删除，不能用更多说明文字弥补没有取舍的设计。
