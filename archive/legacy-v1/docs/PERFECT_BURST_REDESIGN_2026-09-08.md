# 已取消提案：压锅二连爆

日期：2026-09-08。状态：**已取消，未接入正式玩法，不进入实现计划。** 用户决定移除完美判定和提前点火，保留自动出锅与储压调度。当前规则见[移除完美判定](AUTO_BURST_SIMPLIFICATION_2026-09-08.md)。

以下为取消前的历史设计原文与纸面参数，仅用于追溯讨论；其中原型、实现与验收建议均已撤回，不是待办事项。原提案依据为完美回报被等待成本抵消、80 能量提前出锅在活动合同中更快的问题。

**一句话体验：一锅成熟，按住锅盖锁住余压，等金圈亮起松手，让爆米花再炸出一整批。**

普通产出自动完成；玩家的操作决定能否出现第二次爆发。技巧收益是一个完整的新批次，成功后在真实产量、出货表现与合同进度中一起兑现。

**玩家实际怎么玩**

1. 机器正常升温。能量到 100 时完成一锅，下一锅立即开始蓄能；没有蓄压储存时，第一批照常出货。
2. 锅盖开始颤动，原点火位置出现大按钮“按住锅盖”。玩家有约 2 秒决定是否参与。这个邀请时限无需显示精细倒计时。
3. 按住后进入一次固定时长的压锅动作。环形标记向锅盖收拢，锅盖从颤动变为压稳；金圈亮起时，按钮显示“松手，二连爆！”
4. 在金圈期间松手，立刻出现第二声爆响，追加一整批与基础锅等量的出货；提示“完美！再出一锅”，并显示真实新增份数。
5. 没按、提前松手或压得太久，都只是没有追加批次；普通生产照常进行，不扣金币、产量或下一锅能量。结果提示用“普通出锅”，不弹失败面板。

这次操作是一按一松，每个自然满锅只有一次机会。无需连续成功、维持连击层数或重复快速点击。机器升级后只缩短等下一锅的时间，压锅判定的现实时间保持一致。

**首轮参数**

以下数值用于原型，需用实际触屏反馈调整，不是行业标准或已验收数值。

| 项目 | 设计值 |
| --- | --- |
| 满锅条件 | 累计 100 能量 |
| 参与邀请 | 满锅后 2 秒内开始按住 |
| 完美区间 | 从按下起 0.80–1.40 秒之间松开，宽 0.60 秒 |
| 最长按住时间 | 1.60 秒；到时自动结束，本锅不再接受技巧输入 |
| 完美额外产出 | 基础锅 B 的 100%，即基础 B＋追加 B |
| 成功后第二声爆响 | 松手确认后约 0.15 秒，随后集中出货 |
| 首次学习 | 首次免费爆锅后可演示一次；教学的金圈暂停等待松手，结束后恢复正式窗口，也可跳过 |

取消原有 80 能量立即出锅和 92–98 能量判定。普通添料保留原有生产与蓄能功能，已有的每锅次数限制继续生效。压锅按钮与机器添料热区分开；压锅期间的同一指针不触发添料。

**为什么它能解决原来的收益问题**

令 B 为当前基础爆锅产量，现有计算为 `B = 24 × 点击产量 + 8 × 基础自动产量`。新方案所有自然锅都消耗 100 能量，并在成熟时开始下一轮，按得早不会提前重启蓄能。

| 结果 | 每 100 能量获得的爆锅产量 | 下一锅蓄能 |
| --- | ---: | --- |
| 自动或错过 | B | 已在满锅时开始 |
| 压锅失误 | B | 照常进行 |
| 完美压锅 | 2B | 照常进行 |

完美区间内早松或晚松的奖励完全相同；窗口内等待几百毫秒只改变追加批次的到账时刻，不降低持续生产效率。追加出货不增加能量、不补投料次数、不产生新的压锅机会，因此不存在奖励自我循环。

当前双缸机、三项升级 Lv.12 的固定状态下，基础自动产量约 1127.63 份/秒，B 约 21496.43 份，不投料时每 20 秒自然满一锅。只比较长期平均物理产出、无广告/合同/储压/升级的纸面模型：

| 压锅成功率 | 平均每 20 秒产出，含持续自动生产 | 相对纯自动 |
| --- | ---: | ---: |
| 0% | 44048.97 份 | 基准 |
| 50% | 54797.19 份 | +24.4% |
| 100% | 65545.40 份 | +48.8% |

这说明“爆锅部分翻倍”能够在整体产出上形成明显收益，但不能宣称整个工厂收入翻倍。数值由当前产量公式进行纸面核算，尚未接入游戏；不是完整通关、真实成功率或合同收益预测。

**三类合同分别怎样兑现**

| 合同 | 完美带来的实际结果 | 玩家看到的反馈 |
| --- | --- | --- |
| 影院量产 | 追加 B 按现有装箱分配比例进入合同，剩余即时零售；不绕过真实数量上限 | 第二批成品集中进入装车区域，装箱进度大幅前进 |
| 精品礼盒 | 追加真实货量，并提供一次相当于 3 秒当前糖衣加工能力的即时加工额度 | 第二次爆发衔接糖衣滚筒，额外完成一批真实礼盒 |
| 庆典活动 | 基础与追加是两次真实出锅，各计一锅；原三锅要求保留 | 合同从 0/3 推进到 1/3，再到 2/3，而不是只闪“20%” |

精品的加工额度在追加批次实际交付时执行一次：先分配追加货物，再加工已有未加工库存，最多加工库存现有数量，未用额度立即作废。加工速率沿用模块差异，糖衣机仍更有效；不直接把全部原料变成成品，也不生成持续增益或可积攒的加工券。

庆典在没有预存锅时，至少需要两次自然满锅事件即可完成，不能因此说一定要等待两个完整周期，接单时可能已有能量。每份追加出货都如实计锅，不设置“画面出了一锅却不计数”的隐藏规则。

庆典原有高额奖励按更慢交付设计。新玩法使交付变快后，必须同时比较三类合同的现实用时、到手现金和操作量，再决定是否调整庆典奖金。原型不能只验证庆典变爽，也不能直接认定它仍与其他两类均衡。

**与蓄压罐的配合**

自然满锅仍按照现有规则决定出货或储存。储槽空时，基础锅进入储槽，画面显示“压稳还能多存一锅”；此时技巧邀请来自这次自然满锅，不来自以后按下释放按钮。

完美后，追加批次与基础锅作为同一个储压包保存。储槽仍只能保存一个自然锅的储压包，但这个包可以包含基础和追加两批；界面明确显示“已存 2 批”，避免“一锅容量”与实际表现矛盾。储压加成按原 25% 对包内每批各应用一次，成功后的整个包为 `2 × 1.25B = 2.5B`。

点击释放时连续发出包内批次，播放完整两响；储存成功时只表现锁压完成，不提前播放已经出货的效果。储槽已满时，新自然锅继续按原规则直接出货，它的追加批次也直接出货，不借后来腾出的储槽追加储压加成。

流水线自动释放沿用现有条件。储存、手动释放、自动释放及追加出货都不生成压锅机会。判定期间先释放基础锅是允许的；后来成功的追加批次直接跟随原锅包结算，不复活储槽、不再次获得 25% 加成。

**这次爽点如何表现**

普通出锅是第一声干脆爆响。按住时锅盖被压住、蒸汽收束、声音逐渐上扬；金圈亮起时给一次清楚提示。松手成功后，锅盖明显弹起，第二声更饱满的爆响与集中出货同时发生，突出“是我刚才松手触发了它”。

第二批使用当前机器的产出形态：手摇锅出散粒，双缸机双路出杯，多头机齐出整托，流水线发箱，巨塔发整垛。基础批次与追加批次在节拍和出货位置上区分，保留固定实体上限。关掉声音时，金圈、锅盖姿态和“松手”文字仍能完整传达判定。

首次只教一件事：“按住，金圈亮了就松手。”不向玩家展示能量收益公式、冻结报价或结算批次编号。

**实现前必须守住的结算与交互规则**

- 每次自然满锅生成唯一编号。基础锅产量、售价、加工速率、是否获得储压加成在满锅时冻结；同一编号最多生成一个追加批次，不能通过购买升级、重载或重复释放改变已承诺奖励。
- 合同归属在锅包第一次实际出货时确定。接单前存好的完整储压包可以供给新单；已经出过第一批后，追加批次只能跟随原合同。原合同已结束或取消时追加产出按正常售价零售，不转而推进另一张合同，精品加工额度也不转移。
- 追加批次有独立的兑现标记，遵守产出、零售与合同货款的同一分配规则。已进入合同的货物不能同时卖成现金；精品加工不再生产第二份相同货物。
- 追加事件不得直接复用会重置投料额度的自然爆锅逻辑。视觉演出不负责发奖，重复播放不能重复结算。
- 只接受一个触点。按住离开有效区域、切后台或主动打开面板时结束本次技巧，保留已经获得的普通产出和已确认追加奖励。未完成操作不在回归时自动判完美，离线也不补技巧收益。
- 同时最多一个判定。极高输入导致下一自然锅提前成熟时，结束上一次未确认的判定，再开放新机会，不排队；常规中后期的单锅间隔远长于本次操作。
- 压锅期间不主动弹出教学、结算或广告窗口打断；已经确认的第二批若遇页面切换，先保留结算结果，演出之后补播或省略，不丢奖励。

**原型的验收范围**

先验证普通、漏操作、早松、金区两端、晚松和自动结束均只有一份基础收益，完美恰好再多一份；0.80 与 1.40 秒的成功回报相同，所有路径的下一锅蓄能起点相同。

随后固定同一设备、升级、初始能量、储压、广告和合同状态，比较三类合同在自动、50% 成功、100% 成功下的交付时间、最终现金和操作次数，并分别覆盖有无糖衣/装箱/蓄压。另查提前储压接单、判定中完成旧单、存档恢复和释放中再次输入。

最后用真实触屏确认一按一松是否舒服、0.60 秒金区是否可辨认、成功后能否看懂新增批次。再决定最终窗口与奖励倍率。此次方案先完成独立的二连爆闭环，后续再评估是否需要额外成长内容。
