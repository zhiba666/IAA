# 中后期节奏与可玩性改进

更新：2026-09-06。依据本次评估，优先处理长时间等待、操作选择少、完美爆锅反馈被提示遮挡，以及竣工后金币缺少用途。真机验收与软著办理继续暂停。

## 已完成的改动

1. **第 11–20 单分段兑现。** 本单新增产量达到 25%、50%、75% 时，各可预领原订单基础奖励的 20%，帮助玩家提前投资。分段不扣产量，结单扣除已付款；跳过分段仍可领取全额。广告结算明确显示剩余款，避免重复放大已领金币。
2. **两种自选委托。** 完成第 10 单后，从订单面板右上角进入：大批量补货要求接单后的新增产量，适合生产和切档；匠心精品单要求实际完成两次完美爆锅，若接单时已解锁余热，还要实际使用 10 次余热。每张当前主单最多领取三次委托奖励，无倒计时和失败罚金，不消耗主线产量。接单时固定目标和奖励，进度可保存。
3. **完美爆锅反馈立即可见。** 实际爆锅时清除先前的点火提示，让本锅产量和火候加成立即出现；反馈被其他提示、弹层或开工页遮挡时，暂停其显示倒计时。
4. **三件竣工收藏。** 完成 20 张主单并建成巨型爆米花塔后，可从工厂购买城市招牌、金色奖杯、星光灯饰。分别花费 1500 亿、3500 亿、8000 亿金币，后两件还要求完成 1 次、3 次返场订单。购买后永久陈列于场景，总花费 1.3 万亿金币。
5. **推荐、提示和记录接通。** 首页能提示可领分段款、委托进度及收藏目标；委托提供生产档位和火候练习入口，未解锁余热时只教当前可用操作。新增领取、接单、放弃、购买和面板可见曝光记录，默认只在本地内存中保留。

业务边界与接口详见 [规则说明](PROGRESSION_RULES.md)。分段、委托和收藏均覆盖重复点击、过期报价、广告播放互斥、旧存档恢复及精确金币账目。

## 数值对照

使用零金币新档、自然生产、无广告、无离线收入进行 16 条固定路线模拟。下表是每秒点击两次、常规档的可比路线；精品路线的旧版对照也使用原有完美爆锅和余热，避免把旧能力算作新增收益。

| 指标 | 原流程 → 分段 + 补货 | 原流程含点火 → 分段 + 精品 |
| --- | --- | --- |
| 第 20 单完成时间 | 46 分 18 秒 → 40 分 52 秒 | 42 分 24 秒 → 37 分 10 秒 |
| 第 10→11 单间隔 | 220 秒 → 174 秒 | 204 秒 → 154 秒 |
| 第 14→18 单间隔 | 1119 秒 → 1012 秒 | 1014 秒 → 918 秒 |
| 后期最长领奖或购买间隔 | 473 秒 → 116 秒 | 427 秒 → 108 秒 |
| 后期最长纯购买间隔 | 728 秒 → 702 秒 | 660 秒 → 666 秒 |

新增分段和委托明显缩短了兑现间隔，但永久能力购买之间仍可能等待约 11 分钟，尚不能认定这一问题完全解决。三件收藏是有限的竣工目标，不是无限后期成长系统。模拟中主动常规路线在主线后继续自然赚取金币，额外 1548 秒并完成三次返场订单后购齐收藏。

四条完全忽略新增功能的路线，订单与机器时间和原流程逐项一致。分段总账守恒，连续接单再放弃不会产生金币。模拟的低频路线仅降低点击频率，仍每秒检查购买和领奖；脚本点火准确率也不代表真实玩家。这些数据用于判断规则与节奏，不证明乐趣、留存或真实通关时间。

复现：`node tools/progression-analysis.cjs`。详细策略、源码校验值与逐单数据见 [模拟结果](../artifacts/progression-analysis.json)。

## 验证结果

- 全量自动测试 **559/559 通过**，约 3.25 秒；本轮新增 29 项，包含规则、界面、真实输入链路和提示寿命回归。见 测试输出（历史路径：`artifacts/progression-full-tests.txt`，本轮已删除）。
- 浏览器与抖音包已重新构建，11 个模块，脚本包约 258.1 KiB，抖音完整包约 370.6 KiB。代码静态预检通过；两个广告位尚未配置，不能据此认定发布就绪。见 预检输出（历史路径：`artifacts/progression-preflight.txt`，本轮已删除）。
- Chrome 在 320×524 隔离场景中检查订单分段、委托选择与收藏。第 11 单领取 800 万分段款后，结单余额由 4000 万降为 3200 万，累计产量保持不变。
- Chrome 实际点击完成精品委托的两次完美爆锅与 10 次余热使用，领取 125,832,968 金币；完美爆锅的实际产量和火候加成可见。收藏场景三次购买后，金币从 2 万亿变为 7000 亿，全部收藏出现在工厂。
- 最终构建的正式入口正常展示健康游戏忠告，开工后恢复原有存档和待领离线收益；普通领取后显示到账提示并回到可继续经营的首页。

隔离场景由 `tools/visual-check.mjs` 设置测试状态，用于检查显示、点击和结算，不运行自然时间推进、不修改正式存档，也不能充当自然通关记录。本轮没有新增 IDE 或真机验收结论。
