## 验收范围

前 6 单保留教学；双缸机之后，第 7–20 单从影院数量、精品糖衣、活动爆锅三条合同路线中选择。一次仅有一个活跃合同，生产分配给合同后不能同时获得零售收益。两模块槽支持蓄压、糖衣、装箱，单间免费换装；满 100 能量自动免费爆锅，蓄压罐保留 25% 增产和释放。成长任务自动结算。研发、工艺、委托、旧档位和返场移出当前玩法，历史获得的能力保留。

后续调整已移除 80 提前点火与完美火候判定，见[移除完美判定](AUTO_BURST_SIMPLIFICATION_2026-09-08.md)。下文模拟与浏览器结果为本次调整前的合同改版记录，保留原始结果，不代表删除后的验收。

## 检查场景

1. 320 × 524 与 390 × 844 下，分别打开订单、模块和设备面板；逐阶段检查按钮、内容和点击区域。
2. 双缸机起点，默认糖衣加装箱模块接受影院单；观察真实产量、冻结报价、占用产能和交付结算。
3. 单间将装箱换为蓄压，分别接受精品单、活动单；查看糖衣要求、爆锅批次与蓄压上限。
4. 活跃合同期间尝试换装、接受第二单；应拒绝且不扣款、不覆盖已有合同。
5. 生产部分合同后放弃，再接同路线；旧进度不应转移，不能重复领取奖励。
6. 进行中与可交付合同分别内存重载；检查报价、进度、占用收益与订单编号。模拟离线 10 分钟，领取前后检查合同是否被错误推进或双算。
7. 8–10 分钟中期模拟使用固定初始夹具，启动后仅通过公开玩法方法生产、升级、换装、接单与交付；不写入资源，不看广告。至少比较两种配置。
8. 纯自动路线零点击、不释放蓄压、不看广告；必须存在可达的合同交付路径。
9. 旧存档重载保留设备、订单和已购能力；第 20 单结束后不再创建返场单。

## 10 分钟中期原型观察

固定起点为双缸机、第 7 单待选、三项升级 Lv.12、24 万初始金币；夹具历史成长奖励由恢复流程自动结算。之后仅通过公开玩法 API 正常生产、升级、换代和交付，不再写入资源，不看广告。两个配置均按影院→精品→活动顺序循环。

| 配置与操作 | 剩余 14 单完成时刻 | 600 秒内手动操作 | 广告 |
|---|---:|---|---:|
| 糖衣＋装箱，纯自动生产 | 403 秒 | 0 次投料、0 次释放 | 0 |
| 蓄压＋糖衣，按冷却少量投料并释放储压 | 380 秒 | 179 次投料、38 次释放 | 0 |

这是一段 600 秒的观察，其中后半段包括主线完成后的生产，不代表 10 分钟内始终有新的主线目标。

## 冻结经济条件下的模块取舍

同一双缸机、Lv.12、第 7 单状态，接单后不升级、不换代、不看广告。表内为真实交付所需秒数，主动策略仅按允许次数投料并立即释放储压，不额外使用火候点火。

| 配置 | 自动：影院 / 精品 / 活动 | 主动：影院 / 精品 / 活动 |
|---|---|---|
| 糖衣＋装箱 | 20 / 33.75 / 60 | 19 / 33.75 / 56.5 |
| 蓄压＋糖衣 | 40 / 33.75 / 80 | 19.25 / 33.75 / 56.75 |
| 蓄压＋装箱 | 34.5 / 84.25 / 80 | 19.25 / 84.25 / 56.75 |

糖衣使精品加工明显加快；蓄压以主动释放换来更多单锅产量，但放置储存首锅时会拖慢交付。当前固定状态下，主动使用蓄压＋装箱的影院和活动表现与蓄压＋糖衣相同，精品却更慢，说明三种配装的价值并不均衡。装箱在“蓄压且不主动释放”的影院路线仍有可测优势。完整 JSON 报告还记录了交付前现金、占用货款、总入账与每秒入账，避免把等待期间额外零售收入误当成更快的合同收益。

## 发现与修复

- 异常 `factory.equipped` 字符串或对象会在恢复时调用 `.filter` 崩溃：已增加数组类型处理，并回归异常列表、重复模块和非法 ID。
- 收藏恢复曾覆盖旧去重结果：已验证只保留唯一、合法收藏，未竣工工厂不能恢复收藏。
- 保存后的离线广告回执可将 `amount` 篡改为 `1e100` 并成功兑付：恢复时现按冻结离线包的现金部分验证金额和包 ID，异常回执丢弃，已经赚取的普通离线包保留。合法回执仍保持原承诺；把合同货款并入广告现金、增加金额或负数均有回归。
- 一次 `tick(60)` 与 600 次 `tick(0.1)` 的物理产量、现金、占用货款、爆锅数和合同要求一致；旧离线包不能推进新合同，失败广告不丢普通奖励，广告翻倍不复制合同货物。

## 本轮验证结果

- 全量 `npm test`：544 / 544 通过，无跳过用例。保留原生抖音宿主、非 DOM 环境、RAF / 计时器、安全区、音频、存储和广告异常回归；将退役路线专项替换为当前玩法测试。
- `npm run build`：浏览器及抖音发布包生成成功，开发长按默认关闭；`npm run preflight` 代码静态预检通过。两个真实广告位仍未配置，真机验收与软著工作按既有安排暂停。
- Chrome 320×524：实际点击画布切换精品礼盒、接单，观察备货与糖衣加工分开推进，再交付第七单。核对 2707649 合同奖励与 431896.26 待交货款合并为 3139545.26 金币，一次到账并进入下一单。
- 同一 Chrome 夹具中卸下装箱臂、装上蓄压罐，接活动单。QA 时间推进触发储存后，实际点击释放按钮使活动进度由 1 / 3 变为 2 / 3，库存清空，产出与金币事件一致。
- Chrome 390×844：巨塔竣工夹具显示 20 单完成与收藏入口，不再生成返场单；收藏入口可打开。以上浏览器场景未记录运行错误，绘制检查未修改存档。
- 礼盒备货已齐而加工未完时，履约说明改为“后续产出即时售卖”，避免继续显示已不适用的分配比例。设备不足时引导攒钱换代，装箱与糖衣的连续动画事件不触发每帧音效或平台上报。

Chrome 检查使用明确标注的本地内存夹具，不读取或覆盖正式存档，不调用真实广告；模拟与浏览器结果不代表真机性能、玩家留存或广告收入。
