# 渐进解锁与机制引导

> 本文保留初版说明弹窗设计及当时验证。当前已改为[操作引导](ACTION_ONBOARDING_2026-09-08.md)：直接指向真实控件、根据成功动作完成练习、帮助仅主动回看，取消自动说明队列与阅读暂停。

> 最新设备及对应引导请优先阅读[永久设备收集设计](EQUIPMENT_COLLECTION_2026-09-08.md)：双缸机开放六件图鉴，设备永久获得并同时生效，已替代下文空槽、装配与流水线专属放锅。本文件保留前一轮引导设计及历史验收记录。

新玩家先完成一件事，再接触下一种玩法。首页保留一个当前目标；新功能首次开放时，单独说明「有什么用」和「接下来试一次」。说明确认仅记录已读，不代购升级、不接合同、不触发广告。

## 新档节奏

| 进度 | 新开放的玩法 |
| --- | --- |
| 开工 | 点击生产；设置和引导始终可用 |
| 点击 5 次，或累计生产 16 份 | 爆裂玉米升级；纯自动经营也能推进 |
| 爆裂玉米 1 级 | 自动火力升级 |
| 自动火力 1 级 | 前六张累计生产订单、能量说明 |
| 交付首单 | 焦糖配方、成长记录、工厂与换代条件 |
| 交付首单且营业 90 秒 | 可选激励入口；引导不要求观看广告 |
| 电热锅 | 可选品牌合作 |
| 双缸机且完成 6 单 | 每锅三次投料，以及第 7 单影院合同 |
| 完成第 7 单 | 两个空改造槽、装箱臂、糖衣机、礼盒合同 |
| 完成第 8 单 | 庆典合同、蓄压罐 |
| 多头机 | 批量升级 |
| 自动流水线 | 未完成庆典合同中的自动蓄压发运 |
| 爆米花塔且完成 20 单 | 竣工收藏 |

最初六个操作目标依次为基础生产、玉米升级、自动火力、首单、焦糖配方和首次免费爆锅。缺金币时目标明确提示继续生产；之后继续使用现有合同交付、升级建议和换代目标。升级和合同的锁定同时约束界面与游戏实际操作，键盘快捷键不会绕过。

同一进度有多条说明时，每次只展示一条。确认后先回到操作，下一次交互再提示后续内容；主页也可主动点击了解待看的功能。说明面板暂停在线生产和能量，方便阅读后继续经营。离线结算、启动忠告、广告等已有流程不会被新弹层覆盖。

免费爆锅统一在能量达到 100 时自动发生；首次爆锅后继续经营，不再开放手动点火说明或额外操作。旧档已读的点火说明不再出现在引导与回看列表。

## 保存与回看

`state.onboarding` 保存版本、旧档兼容标记及已读说明 ID。只读取视图不改变存档，不发奖励。重启后已读说明不重复出现，未读说明继续保留。顶部「引导」及设置中的玩法说明只列已开放内容，支持分页回看。

没有引导字段且已有经营进度的旧档，在原有机器、合同、永久能力归一化完成后迁移；原来能用的玩法和模块配置继续保留，已有机制的说明一次标记为已读。之后换代新开放的机制仍会提示。新档默认设备槽为空，等第 7 单交付后由玩家选择装配。

## 后续增加机制

在 `src/onboarding.js` 的 `featureAccess` 中定义解锁条件，在 `LESSONS` 中添加稳定 ID、用途、操作说明和目标入口；按钮只导航到实际控件，不代替玩家操作。将同一条件接入 `factory-rules.js` 的操作校验与视图可用性，并在 `interface.js` 中筛选入口。若机制需要实际教学步骤，再加入当前目标选择。

保持 ID 稳定，以便存档去重与回看。修改门槛时须保留旧档已获得的能力，并验证没有金币或解锁条件相互依赖的死路。

## 验证

`tests/onboarding.test.cjs` 覆盖解锁条件、只读视图、说明去重与旧档归一化；`tests/onboarding-flow.test.cjs` 使用实际游戏与应用输入，覆盖门禁、逐步购买、合同交付、暂停、恢复和回看。原有纯自动通关模拟继续使用真实新档；隔离经济与平台行为的历史夹具明确采用兼容模式。

浏览器验收使用 Chrome，检查小屏 320×568 的首次进入、玉米升级及下一阶段说明；各说明与主页同时做不同尺寸、安全区的布局检查。

渐进引导初版的历史验证：`npm test` 565 项全部通过，无跳过；`npm run build` 生成浏览器及抖音发布包，开发长按关闭；`npm run preflight` 代码静态检查通过。这些结果早于移除完美判定，不作为本次调整的验证结果。原有两个广告位仍未配置，未开展真机或平台发布验收。
