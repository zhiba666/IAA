# 当前目标与升级推荐联动

日期：2026-09-06。承接火候和本单进度打磨，将首页推荐与当前目标、订单进度和设备换代所需金币联动。

## 玩家能看到的变化

首页推荐卡给出一个可执行的下一步，并说明收益或差额。购买、领奖和普通领单后会重新计算推荐，弹层打开期间不记录首页推荐曝光。

| 当前情况 | 推荐行为 |
| --- | --- |
| 当前目标已完成 | 领取成长奖励、前往订单装车或查看可换代设备 |
| 当前目标指定升级 | 保持该升级；金币不足显示差额，不切到另一个便宜升级 |
| 新手目标要求点击生产 | 显示每次产量与继续生产按钮 |
| 订单尚未完成 | 优先推荐永久自动生产，自动升级满级后推荐点击升级；显示产量提升 |
| 订单已满足、正在攒换代金币 | 仅在永久自动收入估算显示能缩短攒钱时间时推荐自动或售价升级，否则提示攒钱 |
| 换代金币已备齐、订单未完成 | 推荐只能使用不影响换代的富余金币；否则提示先完成订单 |
| 永久生产升级全部满级 | 继续指向订单及循环订单 |

推荐沿用当前目标系统的优先级，明确追踪的升级目标优先于一般攒钱建议。完整升级面板继续允许玩家自行选择。点击“去换代”进入设备详情，由已有确认按钮完成换代。

## 攒钱估算的范围

估算只使用永久自动收入：等待时间为“剩余金币 / 当前永久自动收入”；购买后为“剩余金币加升级花费 / 升级后永久自动收入”。仅比较当前买得起的自动与售价升级，且要求购买后的估算时间严格缩短。

玩家点击、免费爆锅、临时增益、未领奖励和未来连续购买均不纳入估算，因此这不是实际到达时间或全局最优策略。卡片标注“自动收入估算”，不展示倒计时。比较数据保留在本地 QA 报告，便于复核。订单推荐使用“份/秒”或“份/次”，不会把提高售价描述为加快订单产量。

经济 CONFIG、升级价格、生产公式、任务奖励、订单目标及存档结构保持原有版本。推荐计算为只读函数，不修改游戏状态。

## 实现位置

- src/next-step.js：纯推荐选择与估算。
- src/core.js：新手升级目标明确携带 upgradeKey，金币不足时仍可识别目标。
- src/interface.js：推荐卡、收益与差额文案，保留既有布局和触控区域。
- src/main.js、src/experience.js：接入当前推荐快照与 experience_recommendation_visible 事件；相同推荐不逐帧重复记录，关闭和重新出现可分别识别。
- tools/experience-check.mjs：正式游戏只读报告增加 recommendation。
- tools/visual-check.mjs：生成 10 个内存隔离场景，复用正式核心和渲染器，覆盖攒钱、领奖、保留资金、换代和满级循环订单。页面不连接玩家存档、不推进时间、不接广告。

## 本地复核

按顺序运行以下命令。QA HTML 是本地工具，不进入抖音产物。

~~~powershell
npm run build
node tools/experience-check.mjs
node tools/visual-check.mjs
npm test
npm run preflight
npm start
~~~

默认玩家入口为 http://127.0.0.1:4173/ 。正式游戏 QA 入口为 /experience-check.html?mode=low&width=320&height=568；隔离场景入口为 /visual-check.html，可在 320×568 与 390×844 间切换。本次交付预览服务使用 4180 端口。
