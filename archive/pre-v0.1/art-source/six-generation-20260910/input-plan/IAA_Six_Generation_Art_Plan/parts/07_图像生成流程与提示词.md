# 第七部分｜每个生成任务的执行流程

## 能力探测先于批量生成
A0 在当前 Codex 环境确认：可用图像生成工具/skill、图像参考输入、透明导出、文件落地、额度/并发、运行时依赖。不要假设本次对话的 image_gen 能直接被所有 Codex 子 agent 使用，也不要虚构 CLI 命令。

子 agent 无生图工具时，由它产生合规 generation-job，由具备工具的统一执行者顺序或限流处理；其余切图/装配/QA 仍可并行。主环境也无生图能力时交付 prompts 与明确的 BLOCKED_GENERATION，不得用脚本画出的占位 PNG 冒充已生成资产；不擅自接入新的付费 API 或传出私有源图。

## 标准流水
1. 检索共享清单，给出 reuse/new/repair 决策和依据；已存在且合格不新画。
2. 读取参考图片、style-contract 和本资产 input/slot/output 限定；确认没有遗漏。
3. 先生成一个资产家族的代表性样板；整机空壳、前挡、活动件分离。允许参考板辅助，但不把它当运行图。
4. 检查相机/光源/轮廓/空插槽/无产品无文字，再决定继续。
5. 保留原图、实际 prompt、工具名称/模型标识（工具能提供时）、参考 SHA、时间及实际返回 ID；没有的信息写 unavailable，不编造 seed。
6. 机械导出：裁切完整主体、保留 alpha、等比缩小、颜色优化；变换链写 export-recipe。
7. 在浅色/深色/棋盘格三底上检查边缘；装入 rig 进行前后遮挡和输入输出接点测试。
8. 输出文件、metadata、局部预览和 qa-report。单个资产连续两轮仍失败，停止自动追加，提交缺陷给 A0，不无限重试。

## 提示词模板（将占位字段替换为真实值）
```
为《小小爆米花厂》生成 [asset_id]，用途：[具体独立部件]。
严格匹配附带参考图及已批准的共同样板；正交等距方向，地面两轴
约 (1,0.55)/(-1,0.55)，左上柔光，青绿大色块机壳、灰蓝钢材。
本次只生成 [body/front/head/托具]，不是整屏游戏截图。
机体预留 [N] 个空安装位，不生成工作头、杯子、爆米花或库存。
保留完整轮廓和透明外缘，不改变规定的入料/出料方向。
[目标部件的形状、空洞、近侧挡板、视角与共享比例说明]。
无文字、无金额、无等级数字、无图标、无水印、无角色、无装饰堆物。
透明背景；棋盘格不得成为图片内容。纹理简洁，小屏仍可辨识。
```

前挡/盖板任务需明确是配套图，不独立改变机壳视角；UI 只生成无字标志；数字 1–6 与价格全部程序排版。提示词无法保证精确插槽位置，最终以导出、测量和 rig 拼装验收。

## 生成成本与数量
39–40 为候选独立 PNG 数量，不等于 39–40 次生成。样板阶段先小批，跨 agent 并发受统一队列控制。原图、失败图与衍生图分别存储；失败图不进入预览引用、构建白名单或交付数量。去重后再冻结最终资源量。
