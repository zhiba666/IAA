# 第十部分｜接入交接及总控启动指令

## 阶段 B 的接入清单（单独授权）
由单一集成人扩展 `tools/art-build.mjs` 的资源选择和 rig 合并；保持源图/预览不进包；通过构建生成 `src/art-manifest.js`，不手改生成文件。当前脚本仅选首代、并把出货内容限制为单杯，必须显式恢复合格双杯/箱装 rig，不能只新增 PNG。[R4]

扩展场景路由，使第二至六代不再默默回退旧 Canvas；保留旧显示路径用于明确降级或 baseline，不以删除旧绘制代替新渲染。界面共享皮肤的首代判断、机器点击与入口映射一起核对。若采用分代加载，还要实现资源生命周期与失败回退。[R6][R10]

不得改变 Game 库存/收入所有权、初始能力、价格、存档 schema、迁移边界和自动试运行。实际传给画面的机头/批次/容量来自状态，而不是从截图猜。

仅在隔离集成 worktree 执行当前项目构建/测试与经济回归。执行前记录原日志和工作区；执行 `npm run build`、`npm test`、`npm run preflight`、`node tools/automation-balance.cjs`，以当时真实结果为准，不预填历史测试通过数。由 Git diff 验证数值文件未改。浏览器与抖音包逐文件 SHA 检查，然后记录加载/操作/生命周期；真机未跑必须保留 NOT_RUN。

## 可以直接交给总控的启动指令

请先阅读本计划书及 `tasks.json`，作为 IAA 六代美术总控执行阶段 A。使用当前仓库工作区，不重置用户改动；核对计划基线与当前 HEAD，出差异表后冻结本轮契约。先执行 Gate 0 与 Gate 1，再按 A1–A6 资源家族并行制作，A7 独立验收。

所有 worker 只写本包 `art-source/six-gen/<owner>/`，公共契约/合并清单由总控独占。先复用既有60项候选资源，机器头与产品共享，不按六代复制一套。遵守三工位两段物流、设备与阶段独立、旧批次量保留、自动到账等规则。正式运行文件、存档和经济配置不可改动。

确认当前环境实际具备图像生成能力及可用参考。worker 无生图工具则交 generation-job 给统一生成者；全部环境均无生图能力则明确 BLOCKED_GENERATION，交提示词/装配方案，不得用占位图冒充成图。不得自行启用未授权付费 API。

样板通过后生成初排39–40个必要候选PNG（可因合格复用而减少；增加须变更单），保留原图、提示词、来源、独立alpha、导出配方、rig和QA。每代做entry/upgraded两配置、两视口，共24张基础预览，并覆盖状态矩阵。预算超限必须处理，不把大图塞进包。

每个 agent 返回 HANDOFF：实际产物、引用SHA、验证命令/结果、截图证据、未完成项、跨包依赖和是否触及禁止路径。全部合并后输出 VERIFIED_ART/未完成清单。不要自动开始阶段B接入，不发布、不改规则、不声称真机已通过。
