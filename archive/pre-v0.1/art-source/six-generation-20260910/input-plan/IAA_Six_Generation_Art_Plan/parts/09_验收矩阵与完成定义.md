# 第九部分｜验收矩阵与完成定义

## Gate 0：基线与能力
A0 枚举全部 PNG、manifest/rig 引用，记录实体 SHA、源图路径、未引用资源与脚本副作用；A7 独立复核。记录 Git HEAD/脏文件；不得重置或删除用户工作区。确认图像能力、参考实际可见性及受限路径。若当前 HEAD 与计划不同，先出差异表，再冻结新的实施基线，不倒退仓库到旧提交。

## Gate 1：跨组样板
至少拼成 G02 双头局部和 G06 六头密度灰盒，验证 1 个共用杯、3 类工作头、1 个入口、1 个 UI 底板。两视口检查后才能批量。灰盒仅几何证据，不算成图完成。样板失败先修契约，不能让六条生产线沿错误角度继续画。

## Gate 2：独立资源
每项检查实际 PNG 签名/尺寸/模式、唯一 ID、sourceRect 合法、透明背景、无烘焙文字与棋盘格、无完整轮廓裁切、参考/来源存在、SHA 匹配。非背景边缘 padding 建议至少 2 px；边界有不透明像素需要解释，而非机械认定所有情况不合格。历史 kernel 边缘问题单列回归。自动 alpha 测试不能代替深浅底目检。

## Gate 3：装配/UI/状态
每代 entry 与 upgraded × 两视口 = 24 张基础截图。建立 6代×3工位×3状态（waiting/running/blocked）的54格审查表，先逐项判定可达性。不可达格标N/A而非通过：例如出货完成即结算、没有输出仓，不强造ship堵塞；爆锅没有采购原料流程，不添加虚假“等原料”。对合法多头配置额外做混合状态，不在单头配置强造“混合”。

每代两仓的 empty/one-portion/half/full 为 48 项逻辑覆盖；无需每项独立 PNG，允许组合截图/可重放状态脚本。机器 state 不可能的组合要标为 synthetic-art-only 或排除，不能用非法存档充数。

补充检查：第一代四种连接状态、4份首次/24份常规/36份扩容、取消预留、入口满；双杯与四杯箱装；旧批次1份/新批次2份；最高代仓里仅1份仍可见；升级与扩建保留旧头；单瓶颈/共同限制/观察中；金币不足/锁定/满级/报价过期/二次点击；自动试运行前/累计/中断/完成；六代建成与全改造完成；资源加载失败可见而不伪装已通过。

机壳和带段的输入/输出点转换后建议接缝误差≤2逻辑px（本计划验收目标），但接点计算一致不代表遮挡正确，两者都需检查。命中区域≥44×44，入口优先更大；无文字裁切、无弹层穿透、拖拽放下不触发购买。

## 证据格式
每张预览旁保存 JSON：commit、contractVersion、viewSize、safeArea、generation、configuration、fixtureKind、asset SHAs、执行时间、检查器版本和结论。预览使用独立只读视图 fixture，不写正式存档；加注“美术预览，非真机验收”。

A7 缺陷等级：P0=规则误导/资源缺失/不可操作/重复结算/正式文件越权；P1=接缝/遮挡/风格明显不一致/小屏不可读/预算超限；P2=轻微装饰问题。P0/P1未关闭不得标为 ACCEPTED_ART；预算调整必须有授权依据。

## 完成状态
PLANNED：只有计划。GENERATED：有原图。EXPORTED：有独立件和元数据。ASSEMBLED：有可重放装配。VERIFIED_ART：通过本轮静态/预览验收。INTEGRATED：正式运行引用。VERIFIED_RUNTIME：通过真实构建与状态回归。DEVICE_VERIFIED：真机证据。不得跨级宣称完成。

阶段 A 可证明 VERIFIED_ART，不自动证明后面三项。计划包中的任务目前全部为 PLANNED，本轮没有生成六代美术。
