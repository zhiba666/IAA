# F01 · 六组生产与状态反馈规范

批次 1，2026-09-09。交付是可编辑动效规范，未接入或运行游戏。完整时间轨、资源引用、触发与终止条件见 [motion-spec.json](motion-spec.json)。

生产轨道由每个实际工作头的 `job.progress` 驱动；同一机体上的其他头各自运行。比例 0～1 对应该真实批次的完整加工过程，不能额外运行固定动画周期。出货、安装、扩建则读取现有 `ship`、`upgrade`、`evolve` 成功事件；后续毫秒数只控制可视反馈。

| 组 | 时间轨与姿态 | 等待与完成处理 |
| --- | --- | --- |
| 爆锅 | 0～15% 进入工作姿态；15～78% 独立锅头轻动与受裁切产品；78～100% 收束至出料姿态，少量蒸汽淡出 | 缺料时不产粒；完成堵塞时保留产品，停止加工蒸汽 |
| 落料装杯 | 0～12% 杯位/喷头就位；12～86% 杯内填充按杯口遮罩升起；86～100% 喷头回位、保留满杯 | 上游不足一批时不落料；满杯等下游时不重新灌满 |
| 包装 | 0～25% 实际杯数进入托具；25～75% 压头/箱盖动作；75～100% 完成包装停在出料点 | 包装不新增份数与金币；单杯、双托、箱装取决于本批 `job.amount` |
| 自动出货 | 成功 `ship` 后 650 ms 内沿出货轴离场并淡出，显示已经到账的合计金币 | 750 ms 视觉聚合窗，最多一组成品与一条收入；无事件无收入动画 |
| 安装成功 | 成功 `upgrade` 后 700 ms 内局部星点与勾选；购买后折叠条保留 | 未通过报价/资金/扩建条件不触发；旧批次继续，保留“查看下档”入口 |
| 扩建 | 成功 `evolve` 后 900 ms 内扩展件/仓位标签就位，空插槽以盖板表达 | 保持旧设备头数与正在加工批次；新头仍需另购；六代完成无额外奖励 |

## 组合与真实数据规则

- 每个产品形态读取该批次开始时保留的 `job.amount`。装杯升级为双份时，正在制作的旧单份仍是单杯。
- 箱装内部顺序为 `product_box_open` 后壳 → 本批实际杯内容 → `product_box_front` 前壁 → `product_box_lid` 箱盖；整组产品再位于出货机前挡板之后。前壁不与杯内容合并，箱盖可独立落下。
- 工作头完成但下游满仓时，成品保持原位。其他空闲或加工中的头按各自真实状态表示；不能整机统一抖动、统一填充或统一停机。
- 仓位依次组合后壳、裁切后的少量或聚合内容、前挡板。高代最多使用有限代表性物件，低占用的 1 份仍可辨认，数字独立绘制。
- 消费每次实际派发的收入事件一次；视觉聚合只累加显示用 `amount`、`coins`。动画结束不调用结算，不创建第二笔奖励。
- 已售产品离场可暂代完整货车表现。货车资源属于后续 T01，本批不引入手动发车或领奖按钮。
- 降低动态效果模式保留填充比例、成品姿态、状态文字和真实时序，移除抖动、大位移与星点缩放。

## 静态验收范围

JSON 给出了 idle/processing/complete-wait、混合头、升级旧批次与高频出货聚合的规则。新贴片、杯、托具、箱体与机壳须在装配稿中核对大小、裁切和前后遮挡。蒸汽必须保留真实半透明，离散星点不可被单连通域切图错误删除。

这些文件不声称已实现动画、已绑定事件或已通过游戏状态回归。接入时再核对上述真实数据规则和每项效果的有限生命期。
