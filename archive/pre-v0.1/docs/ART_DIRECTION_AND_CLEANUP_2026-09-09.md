## 2. 后续接入路线与规则边界（本轮不执行）

1. **拆分资源**：从概念图确定机器、输送带、产品、卡车与背景资产清单；从 UI 图提取无字底板、按钮状态和统一图标。运行数值、任务文案、进度填充独立绘制。整张概念图不直接充当可交互生产场景。
2. **核对资源加载与构建流程**：后续接入需要独立资产加载、尺寸/锚点/命中区域和双端包内路径。先核对当时源码与已有素材清单，再补实际缺口；不能根据早期“没有加载流程”的记录重复实现，也不能因存在图片或清单就认定已经接入。
3. **替换场景与 UI 表现**：优先替换 `production-scene.js` 的旧外形、配色与排布，以及 `interface.js` 的旧 HUD、操作区和面板。保留状态读取、生产进度、库存量、报价防重复和安全区适配。3D 体块是视觉目标，本轮没有据此决定更换引擎。
4. **明确新入口对应的规则**：新图有“制作→装杯→装箱→装车”四个视觉环节，当前核心为 `pop/cup/ship` 三工位。首轮可将装箱/装车表现映射到现有出货过程；若要成为独立加工工位，再单独设计库存、吞吐、存档与结算变化。新任务区和出货入口需要独立定义完成/领奖/发货状态，不恢复已退役的合同、图鉴、广告或离线系统。
5. **迁移完成后退役旧绘图**：新场景真实表现缺料、堵塞、在制品和出货；新面板保留金币不足、已满级、升级影响和一次购买校验。迁移相关测试并形成新截图后，再删除旧美术实现、归档旧截图，重新生成发布包。

图中的 `800 金币`、`2.0→2.5 份/秒`、任务 `+120/+100` 和出货 `+300` 是设计示例。目前正式游戏初始能力为 `4/2/6 份/秒`、首次装杯升级为 `30 金币`、每份售价为 `1 金币`。新美术确认不等于这些示例数值已替代配置。

当前为自动出货到账，新图包含手动发车与领奖按钮。接入前需要确定各入口触发的是查看、一次性领取还是发货，不能让视觉结算再次给已经自动结算的货物发钱。实际吞吐继续使用真实完成记录，升级预测继续区别于实测速度。
