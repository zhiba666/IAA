# U03 / F01 · 状态覆盖与装配说明

批次 1，2026-09-09。7 类界面位于 [index.html](index.html)，布局与安全区见 [spec/layout.json](spec/layout.json)。每类可切换静态状态，并同时展示 390×844 与 320×524。所有数值、文字、进度和选择描边属于预览覆盖层；PNG 内没有标签。

## 七类界面与操作状态

| 装配稿 | 可切换样例 | 组合与交互规定 |
| --- | --- | --- |
| 主 HUD | 初始经营、装杯选择、共同限制、升级后观察 | 两种 HUD 底板分别承载金币/实测出货，设置独立 44×44；近 10 秒更新中不伪装成即时稳定产出 |
| 工位改造区 | 可买、金币不足、需先扩建、已满级、报价失效 | 主/次/禁用按钮复用；失效报价重新查看后才能购买；长原因独立文本，不挤进小按钮 |
| 改造详情 | 加工中、等料、完成等下游、有料不足一批 | 头数、批量、在制量、实测通过量分开；不足一批样例明确属于后续批量配置，首代不虚构双份能力 |
| 购买后折叠条 | 已安装、持续观察 | 使用紧凑条与勾选图标；“查看下档”是独立入口，不复用刚购买按钮继续购买 |
| 扩建目标卡 | 销量未达标、均速未达标、金币不足、可扩建、六代完成 | 分项显示销量、均速、价格条件；新增仓位/解锁配置分开；六代完成为完整状态稿，不表示首代已进入六代 |
| 设置 | 声音/振动开启、关闭、保存失败 | 共用图标，开关文字独立；错误提示留在面板内，面板遮挡首页提示时仍可见 |
| 重开确认 | 等待确认、取消入口强调 | 明确当前版本进度影响；确认、保留进度分别占至少 44×44；预览不执行重开或写存档 |

首代固定数值例：爆锅 4、装杯 2、出货 6 份/秒；待装/待发仓位各 12；首个装杯改造 30 金币、设备 2→6、预计整线约 2→4。来源仅用于检查当前玩法字段与文字准确性，不复制旧版造型。详情中的批量不足、满级、六代完成是必须保留的跨阶段异常/终态样稿，屏幕会明确标注。

第一代到第二代条件已核对 `src/factory-rules.js`：180 金币、累计销售 100 份、均速 3 份/秒，两仓容量均由 12 增至 24。均速达标会保留；短暂堵塞不会撤销此前达标。当前扩建失败原因先检查均速、再销量、最后金币，与 `src/core.js` 一致。

扩建样例是互相独立的静态快照：销量不足为销售 76 / 持币 46 / 已花 30；均速不足为销售 200 / 持币 200 / 未改造；金币不足为销售 100 / 持币 70 / 已花 30；可扩建为销售 210 / 持币 180 / 已花 30。均满足当前每份售出 1 金币的账面关系；销量不足时资金也未满 180，但按真实判断顺序首先显示销量原因。样例均速与库存是排版取值，未宣称来自游戏实测记录。

## 机器、库存与生产状态

| 对象 | 必须区分 | 静态表达与后续绑定要求 |
| --- | --- | --- |
| 单工作头 | 等料 / 加工 / 完成待下游 | 机体不变，独立头姿态与产品内容变；无实际批次不播放落料 |
| 多工作头 | 一个加工、一个完成堵塞、一个等料 | 同机体不同插槽独立姿态；不能用一个整机进度覆盖所有头；本批只定规范，首代不装多头 |
| 升级中的旧批次 | 旧单份与后续新双份 | 每批使用其自身 `job.amount`，升级不改旧杯数或箱内容，不重置进度 |
| 待装/待发仓 | 空 / 少量 / 接近满 / 满仓 / 不足一批 | 同一后壳、内容裁切、前挡板复用；内容多少由真实库存驱动，数字独立；1 份在大仓仍应可見 |
| 输送 | 空带 / 搬运 / 下游堵塞 | 带面与前挡板分离；产品只有真实转移时移动，不循环制造产品 |
| 选择 | 未选 / 选中 | 独立地面底色或轮廓，避免把原图整体染色导致产品难辨 |
| 生产限制 | 单一 / 共同 / 升级后观察中 | 图标加短文案；等待不等于瓶颈，必须读取诊断结果 |
| 出货收入 | 无事件 / 一次 / 高频事件 | 仅实际 `ship` 事件触发；高频反馈合并显示实际总额，动画不参与收入结算 |
| 扩建 | 保留旧配置 / 已买新配置 | 代数与已购配置独立；刚扩建画空插槽盖板，已买才增加工作头 |

## 组件状态与布局规则

按钮常态用主/次纹理；按下用 1 px 位移与轻微明暗；禁用使用禁用底板；选中为独立细轮廓。开关、选择和进度覆盖层可用 CSS/Canvas，未生成整屏效果图取代素材。

每个预览视口采用安全区、HUD、伸缩观察区、底部面板的顺序布局，禁止面板绝对定位覆盖三工位。紧凑视口保留至少 144 px 观察区，省略辅助段落但保留原因、关键数值与操作。默认顶部/底部 8 px，另可切换顶部 24 px；后续真实安全区采用 `max(safeTop, menuBottom + 5)` 计算内容起点。

新卡片为 384×115，紧凑条为 384×78。九宫格按源像素四边各 32，中心分别 320×51 与 320×14，均为正面积；CSS 的 `border-image-slice:32 fill` 未使用百分比。紧凑条只用于横向折叠状态，展开的大面板仍使用卡片/面板纹理。

关闭、设置、详情箭头、工位选择、购买、开关、确认、取消均至少 44×44 逻辑像素。正文 11～12 px、说明 10～11 px、主数值 17～19 px；按钮/价格不使用省略号隐藏关键条件。未来更长文案与更大安全区应在面板内部滚动，不能压缩点击区或覆盖观察区。

`window.artPreviewReport` 提供当前引用加载结果、实际视口尺寸、页面内容高度、场景高度及小于 44 px 的按钮列表，供统一 Chrome QA 使用。图片透明边缘和九宫格效果仍需人工查看，不能由加载成功代替。
