## 设计与资源

现有门脸、三位角色、两款商品、取货袋及共享货架前后层共 9 项继续引用；详见 [复用清单](reuse-manifest.json)。新增环境把原来的订单卡片排版组织成有前后关系的直售庭院。

| 新增资源 | 导出规格 | 用途与约束 |
| --- | --- | --- |
| `scene_direct_sales_courtyard` | 640 × 960 PNG，不透明 | 薄荷工厂外墙、奶油铺地。后排放门脸，中部留两顾客位置，下部留货架；低对比背景不压过订单。按比例 cover，非无缝贴图，禁止平铺。 |
| `scene_pickup_counter` | 640 × 242 RGBA PNG | 青绿金属框、奶油面板、空连续台面。用于服务前景和袋子支承；只占一个平面层，不能冒充已拆层机械或动画。 |
| `scene_factory_wayfinding` | 244 × 256 RGBA PNG | 向左工厂导向牌，以爆米花图案指路；不烘焙文字或按钮。源图微弱 alpha 像素保留，因此透明画幅较可视主体更宽。 |

统一近正面 3/4 视角、略露右侧、约 20–25° 俯视及左上柔光。用青绿金属与奶油色连接原有门脸，商品红白条纹仍作为视觉焦点。导向牌是环境提示；实际场景切换应使用独立可点击界面。

三张导出合计 **811,705 B（约 793 KiB）**，RGBA 尺寸估算 **3,326,976 B（约 3.17 MiB）**，仅统计新增三图。复用图、Canvas、GPU 副本及宿主缓存不包含在此数值中，不能当作真机内存。

## 图层和交互交接

1. 庭院背景 → 旧门脸及窗口售货员 → 导向牌。
2. 两位顾客 → 新取货柜台 → 两个订单袋；袋中商品按后袋、商品、前袋壁及近侧提手顺序绘制。
3. 底部货架按旧 `cups_rack` 的 512 × 429 装配合同，先后层，再商品槽位，最后前栏。
4. 顶栏、订单气泡、缺口提示、可用/预留数量及目标高亮由界面绘制，不写进 PNG。

取货袋沿用 `src/v13-showroom.js` 的原图裁剪多边形，只适用于当前 179 × 192 PNG。货架复用原前后层、槽位和内容裁剪区；更换这些基础图片后必须重新校准。柜台与路牌整张等比绘制，包围框不充当触控区域。

首单只强调原味配货；混合状态展示两位顾客和两种产品，已配数量与仍缺数量分开；成交状态用装袋和完成提示表达结果。正式接入时应以真实结算事件驱动，不能由动画加钱。共享货架引用同一库存，不增设跨场景搬运步骤，也不加入耐心倒计时。

手机装配采用 390 × 744 逻辑画幅，并提供 320px 宽缩放参考。短屏网页允许纵向滚动；实际游戏的固定货架、安全区和触控目标需在后续接入时单独布局和验收。
320px 缩放图中的库存预留与辅助说明较小，属于美术构图参考；接入时应提高字号并独立设置触控区域，不能直接照搬整张缩放图作为游戏 UI。

## 重做导出与预览

在项目根目录运行：

```powershell
node art-source/v1.3-scenes/build.cjs
node art-source/v1.3-scenes/build.cjs --verify
node art-source/v1.3-scenes/qa-board.cjs
node art-source/v1.3-scenes/render-offline.cjs
node art-source/v1.3-scenes/serve.cjs
```

服务器仅绑定本机，地址为 `http://127.0.0.1:4175/art-source/v1.3-scenes/`。

离线预览使用 `@napi-rs/canvas` 执行本地 `preview.js` 的 Canvas 绘图；其他机器可通过 `IAA_CANVAS_MODULE` 指定其安装目录。

构建使用项目可解析的 `sharp` 或 Codex 已配置依赖；其他机器可用 `IAA_SHARP_MODULE` 指定其安装目录。导出只对生成图做真实 alpha 包围框裁切、等比 Lanczos 缩小、4px 透明留边和 PNG 无损压缩，不程序抠图或改色。背景不做透明裁切。原始源图保留不动，未来可确定性重做导出；重新运行 AI 提示词不保证逐像素复现。

本目录的制作脚本不写入 `assets/`、Web/抖音构建目录，也不加入 87 张基础预载、18 张 v1.3 清单或五图工艺补充清单。后续运行接入由 `tools/v13-scene-art-build.mjs` 的新增清单管理按需加载。
