**IAA / GAME DESIGN**

客户驱动经营 × 新产品成长

**从“等待金币”走向“为客户做出新的爆米花”。**

> 场内点击助力与配方生产，场外拖动成品完成订单；基础自动化逐步接管重复劳动，六代设备以新工艺和新产品持续提供成长目标。

**决策摘要**

## 执行摘要与版本边界

**v1.3 的核心不是增加更多需要搬运的货物，而是让“为谁生产、生产什么、为何升级”成为玩家持续行动的理由。**

### 版本主张

将《小小爆米花厂》从单线产能增长，改为“客户需求驱动的轻经营增量游戏”。保留点击助力、真实流水线和可购买自动化；新增场外直售区，以订单交付产生收入，以新产品和新工艺产生升级欲望。

> **新的价值链**
>
> 客户提出需求 → 安排配方与生产 → 成品进入货架 → 拖动配齐订单 → 成交获利 → 解锁新设备、新产品与新客户。

### 建议采用三层范围，避免把蓝图误当交付承诺

| **层级** | **本报告定义** |
| --- | --- |
| 核心可玩验证 | 两个场景；原味、焦糖两种商品；最多两位客户；点击助力；批量拖动交付；基础售货员与简单按缺口补货。 |
| 六代完整蓝图 | 六代设备与七款商品全部给出设计。第三至第六代的并行、淋酱、成型与礼盒工艺作为后续扩展，不算首轮已交付功能。 |
| 暂不纳入 | 强制限时、变质、烧糊惩罚、随机配方抽取、复杂员工养成、自由装修、多种材料货币、广告与离线收益。 |

### 关于现有六代工厂的保护

前两代只是新玩法的首轮验证范围，不代表删除 v1.1 已有的第三至第六代进度。建议先以独立试玩存档验证；未完成高代兼容前，不强制覆盖旧档、不把旧工厂降回第二代。正式替换入口前须通过迁移验收。

文档性质：设计建议稿，不是已经实施的开发规格或发布公告。用户已提出的方向、本报告补充规则与待验证数值在文中分别说明；未假定 v1.2 已实现。

**从试玩问题出发**

## 01 设计依据与目标

**先修复主动参与与成长目标，再增加内容量。**

### 已核对的 v1.1 基线

本次读取的仓库 main 指向 052cfe8，应用版本为 1.1.0。正式玩法为爆锅、装杯、出货三个工位和 A/B 两段物流；点击产量已停用，点击机器主要打开改造窗口。后台暂停，不补离线收益。[\[S1\]](https://github.com/zhiba666/IAA/blob/052cfe85286e65c76598373a073f7b3bf13823b6/README.md)[\[S2\]](https://github.com/zhiba666/IAA/commit/052cfe85286e65c76598373a073f7b3bf13823b6)

当前 core 在出货工位加工完成时同时记入售出数量、金币与累计收入；设备换代主要改变通道、批量、加工周期、仓容及等级开放。客户售货须改变结算与库存结构，不只是新增页面。[\[S3\]](https://github.com/zhiba666/IAA/blob/052cfe85286e65c76598373a073f7b3bf13823b6/src/factory-rules.js)[\[S4\]](https://github.com/zhiba666/IAA/blob/052cfe85286e65c76598373a073f7b3bf13823b6/src/core.js)

| **试玩反馈** | **设计诊断** | **v1.3 回应** |
| --- | --- | --- |
| 只能等金币 | 自动化接管搬运后，缺少新的主动目标。 | 用客户订单提供当前任务；点击助力影响真实加工。 |
| 玩法模块太少 | 选择集中在同一条线的产能优化。 | 增加配方安排、库存分配与客户优先级，不堆独立小游戏。 |
| 高级设备不吸引人 | 数值更强，但缺少明确的新用途。 | 每代至少一项新工艺与一款招牌产品，升级后立即可体验。 |

### 四条设计原则

操作有因果：点击推进加工，拖动分配现有成品，只有真实成交产生销售收入。成长有差异：更高级意味着能做新品、能并行或能组装，而非单纯提速。自动化有兑现：学会的重复劳动可被可靠接管。轻经营无催促：普通客户不倒计时，不操作也不扣钱。

### 成功应如何判断

关注玩家是否愿意在自动化后选择下一步，以及能否用“我要制作焦糖、完成混合订单”等具体用途解释升级动机。点击更多、拖动更多、界面更多，都不能单独证明可玩性提升。

证据边界：仓库已有功能与运行验证不等于本设计经过试玩。本轮没有执行游戏测试，也没有验证留存或付费提升；本报告的体验效果均为待验证假设。[\[S5\]](https://github.com/zhiba666/IAA/blob/052cfe85286e65c76598373a073f7b3bf13823b6/docs/releases/v1.1.md)

**让每个阶段都有明确目的**

## 02 核心循环与新手路径

**玩家从“亲手完成第一单”，成长为“安排工厂自动满足不同需求”。**

### 两条同时成立的循环

短循环：看需求、看缺口、生产、配货、收款。长循环：成交积累资金、解锁工艺、制作新品、遇见更丰富的订单，再用自动化接管已经熟悉的操作。场内与场外使用同一工厂状态和同一前台模拟时钟。

| **阶段** | **玩家经历** | **设计目的** |
| --- | --- | --- |
| 第一单 | 一位客户只要少量原味；完成必要工序，再把货架上的产品拖给他。 | 看懂“生产不等于赚钱，交付才成交”。 |
| 第一次助力 | 订单缺货时点击明确的助力区，观察真实批次提前完成。 | 让主动操作有立即可见的结果。 |
| 第一次自动化 | 场内 A/B 各段学会一次后尽早开放低门槛自动转运；首代可雇基础售货员。 | 不长期叠加场内搬运与场外交付。 |
| 第二代解锁 | 提前预览焦糖桶；买到裹糖机便可生产，不追加一串研究门槛。 | 兑现升级欲望。 |
| 首张混合订单 | 客人要原味与焦糖；玩家安排批次并分次配货。 | 引入生产顺序与库存分配。 |
| 持续经营 | 基础订单能自动完成；玩家改优先级、助力缺货工序、准备下一项能力。 | 把自动化之后的空档变为选择空间。 |

### 原型节奏假设，不作为硬性时长承诺

第一单以 60 秒内可完成为观察目标；场内物流自动化、基础售货与新品预览应在前期连续出现。第二代可先以约 6～10 分钟到达作为调参起点，新设备买到后约 60 秒内应能看见第一份新品。具体价格、数量和时长需要重跑模拟并通过真人观察调整。

> **重要的难度边界**
>
> 新品可在售货自动化之前展示，但混合订单教学不应发生在玩家仍需频繁维护两段场内物流时。不要同时教拖货、切配方、切场景和多品配货。

**两个场景，一份库存**

## 03 场内、场外与手势分工

**场外是一处工厂直售区，不是需要再搬一遍货的独立商店。**

| **区域** | **核心信息** | **主要操作** |
| --- | --- | --- |
| 场内生产区 | 正在生产的配方、真实在制品、工位状态、当前订单缺口。 | 点击助力；安排下一批配方；查看改造；初期场内拖货。 |
| 场外客户区 | 最多两位客户、产品图标、所需与已配数量、整单报酬。 | 选择先服务谁；把对应成品拖入客户取货袋。 |
| 场外成品货架 | 产品名称、可用量、订单预留量、容量。 | 一次拖动一批；无数量输入弹窗。 |
| 跨场景摘要 | 当前目标、缺货产品、仓满或停机提示。 | 一键切换；不依赖反复切屏记忆订单。 |

### 不做跨屏搬运

包装完成的产品直接进入共享成品库存。场外货架只是该库存的一个可视化入口，不再增加“从工厂拖到场外”的运输步骤。切屏只改变视图，不能重新创建工厂或重复推进时间。

### 输入区域明确分离

机器操作把手或助力按钮负责点击加工，扳手图标负责改造，货盘负责拖运，场景按钮负责切换。一个手势不能同时触发助力、购买或交付。保留现有报价校验、拖动结束防误购与模态优先级等基础保护。[\[S1\]](https://github.com/zhiba666/IAA/blob/052cfe85286e65c76598373a073f7b3bf13823b6/README.md)[\[S5\]](https://github.com/zhiba666/IAA/blob/052cfe85286e65c76598373a073f7b3bf13823b6/docs/releases/v1.1.md)

开始拖动后高亮可接收的客户，显示本次真实可配数量。拖到错误产品、错误客户或空白处回弹，不损货、不扣款。一个货架拖影只表示已有库存的临时预留，不是新复制的商品。

### 切屏、失焦与辅助操作

拖动期间切屏、打开窗口、双指介入或切后台，取消临时拖拽预留。已经成功放入客户取货袋的订单预留继续保留。可提供“点选产品后点客户”的辅助方式，调用相同核心命令；主要体验仍为连续拖动。

另一场景继续运行，不等于应用进入后台继续生产。v1.3 建议仍保留后台暂停、不补离线收益；不把离线经济并入本次改造。

**数量、预留与成交必须一致**

## 04 客户订单与交付规则

**拖动负责配货；整单配齐后，核心状态一次性完成交付与结算。**

### 订单生命周期

> **状态顺序**
>
> 客户到访／生成订单 → 待配货 → 部分配齐 → 全部配齐 → 成交已结算 → 客户离开。普通订单可取消；取消只释放预留，不退还尚未支付的钱。

客户出现时即可配货，无需额外点击“接单”。每笔订单绑定唯一标识、产品数量与固定报价；设备升级、菜单切换或客流调整不能改变已出现订单的报酬。

| **规则** | **建议定义** |
| --- | --- |
| 批量交付 | 本次配货量取可用库存、客户剩余需求与交付批量上限三者的最小值；余货留在货架。 |
| 部分配齐 | 产品进入订单预留状态，仍计入仓容，不能被另一订单、售货员或组装工序使用。 |
| 全单成交 | 原子地扣减预留库存、记录售出、发放销售收入与订单奖金，并标记已结算。最后一次正确拖动即可触发，无二次收钱按钮。 |
| 重复与取消 | 重复松手、重复事件、重读存档不能重复结算；取消未成交订单只解除占用。 |
| 普通客户 | 无强制耐心倒计时、无失败扣款；加急单放入后续可选扩展。 |

### 订单示例

客户需要原味 ×4、焦糖 ×2。先放入原味后显示“原味 4/4，焦糖 0/2”；此时不发钱。焦糖配齐后订单整体完成，客户拿走商品并支付固定报价。产品动画由结算事件驱动，动画播放失败不应影响真实账目。

### 避免不可完成的订单与仓库僵局

订单只要求已具备生产能力的产品，数量须适配仓容并保留加工周转空间。按产品设置补货上限；保留能消化基础库存的小订单，并允许免费取消未完成订单。预留不是额外仓库，不能用多个客户无限扩容。

基础客流负责稳定收入；尚未解锁新品的“愿望客户”只能作为独立预告，不占订单位、不阻断赚钱。

**操作逐步升级，而不是逐步消失**

## 05 点击助力与自动化

**点击推进真实加工，拖动分配有限商品，自动化接管已经学会的重复劳动。**

### 点击助力的作用与边界

点击可操作工位，给当前合法批次增加少量加工进度，或在上限内提升短时加工效率。效果随该工位的基础能力成长，避免高级阶段点击仍只固定增加一份。缺料不造货，满仓不穿透容量，不直接加金币。

初版不加烧糊、过热、失误扣款或节奏判定。助力频率和持续增益设上限，可配合按住助力的辅助选项，避免最快连点成为唯一有效策略。停止操作后基础加工继续。

| **自动化层级** | **建议功能** | **开放节奏** |
| --- | --- | --- |
| 场内转运 | 接管 A/B 标准物流，优先处理合法、未预留的批次。 | 各段体验一次后尽早开放；多品教学前优先减轻场内劳动。 |
| 基础售货员 | 从现有库存配齐普通订单并成交，不抢手动已预留库存。 | 首代可获得；不是高级设备才有的能力。 |
| 简单补货规则 | 根据当前普通订单缺口安排后续配方批次；无缺口时按库存目标补货。 | 与第二代混合订单一起验证，防止售货员一直等焦糖。 |
| 高级调度规则 | 常客优先、库存保留量、单品与复合商品分配、多线并行。 | 第三至第六代扩展，逐步增加控制深度。 |

### 自动售货的公平调度

售货员优先接续可完成的普通订单，并按等待时长处理同优先级任务。长期缺货订单需要触发补产提示，而不能被无限跳过。手动订单可切换由售货员继续处理，但必须明确移交，不能一边拖货一边被自动系统抢走。

### 不能用“必须停手”作为主线验收

当前试运行依赖无人搬运窗口，手动操作会影响其进度。[\[S4\]](https://github.com/zhiba666/IAA/blob/052cfe85286e65c76598373a073f7b3bf13823b6/src/core.js) 建议将连续无人运行认证改为可选成就；扩建检查设备能力、经营里程碑和资金，不要求玩家刻意不操作。主动助力产量与无人运行预测也必须分开显示。

验证主动收益时，应在相同设备、订单序列和自动化配置下比较；更高收益不应以强制持续操作或自动化故意失灵为代价。

**从街角零食到庆典礼品**

## 06 六代设备总蓝图

**六代设计以工艺升级为主线；同一条成长路线同时改变产品、画面与经营选择。**

| **代际／设备** | **新增招牌商品** | **新增能力** | **版本定位** |
| --- | --- | --- | --- |
| 一代 / 街角小爆锅 | 经典原味杯 | 基础爆制、装杯与客户交付。 | 核心验证 |
| 二代 / 琥珀裹糖机 | 琥珀焦糖桶 | 裹糖工艺；单线切换配方。 | 核心验证 |
| 三代 / 双舱拼味机 | 浓香芝士盒 / 甜咸双拼桶 | 双路并行；两种散料组合装桶。 | 后续扩展 |
| 四代 / 双酱瀑布机 | 黑白巧脆杯 | 淋酱、覆层与自动冷却。 | 后续扩展 |
| 五代 / 星模脆棒机 | 星星爆米花棒 | 焦糖散料成型、插棒与封袋。 | 后续扩展 |
| 六代 / 庆典组装塔 | 星光庆典礼盒 | 调用多种未售成品，自动配套组装。 | 后续扩展 |

### 代际、工位等级与产品能力分离

工厂代际表示新增工艺，工位等级表示产能升级，产品能力由明确解锁项控制。三者不能共用一个“等级越大就都能做”的隐含判断。设备可改名，但不要通过重排数组破坏旧档对应关系。[\[S3\]](https://github.com/zhiba666/IAA/blob/052cfe85286e65c76598373a073f7b3bf13823b6/src/factory-rules.js)

### 扩建是增加能力，不是抹去旧工艺

后续设备保留之前的产品路线。画面可以沿原有工厂骨架逐步增加滚筒、双舱、淋酱、成型和组装模块。售货、场内物流等已购买能力持续有效，不因换代重新锁定。

> **本路线的四个强记忆点**
>
> 焦糖的光泽 → 双拼的组合 → 星星棒的形态变化 → 礼盒对整座工厂能力的汇总。高级产品必须能从轮廓与工艺被认出来，不能只换色。

七款商品是本轮完整设计总数，包含基础原味。第三至第六代未进入首轮核心开发范围时，只展示诚实的后续预告，不出现可购买但不能使用的设备。

**核心可玩验证范围**

## 07 产品卡：第一代与第二代

**先把“我想解锁焦糖”变成一次完整、可亲手兑现的升级体验。**

### P01 经典原味杯｜街角小爆锅

产品表现：红白条纹纸杯，浅奶油色、不规则的爆米花堆出杯口。识别依赖纸杯轮廓、条纹与产品图标，不只靠颜色。设备采用可见颗粒弹起的小玻璃爆锅，并保留清楚的助力操作区。

生产与用途：基础爆制后装杯、包装。原味承担短链补货和稳定基础订单，后期仍保留需求。玩家先学会真实生产与交付，不在这一代引入复杂材料采购。

订单示例：街角顾客要原味杯 ×4。点击助力可让该批次提前完成；货架上有足够库存时，一次拖动配齐，不要求四次单杯搬运。

### P02 琥珀焦糖桶｜琥珀裹糖机

产品表现：有光泽的琥珀色颗粒，少量焦糖连结，使用矮胖纸桶和糖滴图标。设备新增倾斜铜色滚筒与透明糖浆罐。重点演出是糖浆流入、滚筒翻拌、亮晶晶成品整批倒出。

生产与用途：基础爆米花进入裹糖阶段后再装桶。第一版糖浆仅作为工艺表现，不另开采购、库存和货币系统。原味与焦糖先共用主要生产能力，配方切换只影响下一批，旧批次保留产品身份。

订单示例：家庭客户要原味杯 ×2、焦糖桶 ×1。焦糖可设定更高单件报价，但加工步骤也更多；是否更划算须结合工时、客流和仓位判断。

| **升级前的期待** | **购买后的兑现** | **本代需要验证的选择** |
| --- | --- | --- |
| “我想做出这种发亮的焦糖。” | 买到设备即可生产基础焦糖；安排一笔小额新品体验订单。 | 先补原味回款，还是生产焦糖完成混合订单？ |

初版不要在买到裹糖机后再要求抽取配方、完成长期研究或购买许可证。首款新品的使用权就是升级奖励的一部分。

**并行与深加工扩展**

## 08 产品卡：第三代与第四代

**第二代学会切换；第三代学会并行；第四代学会选择哪些批次继续深加工。**

### P03 浓香芝士盒｜双舱拼味机

产品表现：细密金黄调味层，带折角的小方盒与芝士图标。方盒轮廓与原味杯、焦糖桶区别明显。工艺为基础爆米花进入调味舱后装盒；作为咸味基础商品独立出售。

### P04 甜咸双拼桶｜双舱拼味机

产品表现：宽口双格桶，一边焦糖、一边芝士，俯视可直接看出分区。设备左右两舱可同时安排不同配方，中间双口机构把两种散料装入同一桶。

示例配方：1 单位焦糖散料＋1 单位芝士散料 → 1 桶双拼。散料是加工中间品，不是拆开已经包装或售出的成品。此配方只定义设计关系，实际单位和产量由配方表统一确定。

经营选择：焦糖可以独立装桶出售，也可留给双拼。多产品订单是“客人分别买两样”；双拼是具有独立配方、图标、库存和加工过程的一件商品，不能混为一谈。

### P05 黑白巧脆杯｜双酱瀑布机

产品表现：深色巧克力覆层上交错白色细纹，放入透明杯并配深色纸套；不可只做一杯深棕色颗粒，避免与焦糖混淆。设备有深浅两条淋酱管、慢转输送盘和透明冷却罩。

生产与用途：基础爆米花经过淋酱、覆层与自动冷却后装杯。等待由机器处理，不增加必须及时收取的动作。玩家决定哪些批次直接作为基础商品出售，哪些投入占用更久的深加工模块。

| **客户需求示例** | **玩家新增的经营判断** |
| --- | --- |
| 客户甲：焦糖桶 ×2；客户乙：双拼桶 ×1。 | 先兑现焦糖，还是留料等待芝士？ |
| 甜品店：巧脆杯 ×3、焦糖桶 ×2。 | 如何分配基础产能与深加工时间？ |

第三、四代的新增工序应自动衔接。不要因为多了两种工艺，就再要求玩家手动搬两段货。

**形态变化与综合代表作**

## 09 产品卡：第五代与第六代

**后期吸引力来自“做成什么”，而不是让顾客要求更多次拖动。**

### P06 星星爆米花棒｜星模脆棒机

产品表现：用焦糖爆米花组成厚实五角星，保留颗粒纹理，下方插短棒并套透明袋。它必须看起来由爆米花制成，而不是一块光滑糖果。设备通过星形模具、下压成型、弹出、插棒和封袋形成可见过程。

示例配方：2 单位焦糖散料 → 1 支星星棒。焦糖既能直接装桶，也能成为成型原料，形成基础订单与深加工订单之间的库存取舍。点击可助力当前压模批次，但不做失误整批报废的节奏游戏。

客户示例：派对采购要星星棒 ×4、双拼桶 ×2。后续可增加爱心或月亮模具，初期作为同类商品的外观扩展，不立即扩张为大量独立库存。

### P07 星光庆典礼盒｜庆典组装塔

产品表现：带透明展示窗、分格内托和提手的硬质礼盒，能看到里面的双拼桶、巧脆杯与星星棒。设备从不同高度输送带接收完整单品，完成展开盒体、装入、封盒与装饰。

> **首款固定礼盒配方**
>
> 甜咸双拼桶 ×1＋黑白巧脆杯 ×1＋星星爆米花棒 ×2 → 星光庆典礼盒 ×1。全部组件必须是真实、未售出、未被其他订单预留的成品。

组装完成后，组件库存减少，礼盒作为独立成品入库。客户买两盒时只需按批量拖动礼盒，不重新交付盒内每件商品。组件只有最终卖给客户时才贡献销售收入，不能组装时先卖一次、交礼盒时再卖一次。

经营选择：把现有单品立即出售，还是预留给礼盒获得综合订单回报？后期按缺口自动补产和多线调度在这里发挥作用，玩家决定优先级，不重新沦为搬运员。

设备升级语义：“把整座工厂的拿手产品装进一份礼物”。六代顶点应是可见的综合成果，不是一个尚未兑现的新倍率。

**同一种原料，可以通向不同商品**

## 10 配方、库存与生产调度

**复合产品增加深度，但必须有明确配方与有界库存，不能把所有商品简单相加。**

| **原料／中间品** | **可进入的生产路线** |
| --- | --- |
| 基础爆米花 | 直接装原味杯；进入裹糖、芝士调味或巧克力深加工。 |
| 焦糖散料 | 装焦糖桶；与芝士散料拼桶；进入星模成型。 |
| 芝士散料 | 装芝士盒；与焦糖散料拼桶。 |
| 双拼桶、巧脆杯、星星棒 | 独立出售；作为完整未售组件进入礼盒。 |

### 生产调度建议

v1.3 首轮只有原味与焦糖，可采用“下一批配方＋按订单缺口补货”两种模式。自动模式先补当前普通订单缺口，无缺口时按各产品目标库存生产。单批开始后锁定配方；切换只影响未开工批次。

第三代增加两路可独立安排的加工舱。排产时同时检查输入、目标仓位、订单预留和工位能力，避免只因高价就让一条产品独占生产。更复杂的优先级编辑器留在后续，不必一开始开放几十个规则选项。

### 仓容与预留

每种产品设置合理上限或保留仓位，同时设置总容量。订单预留与临时拖拽都属于现有库存的占用；两者不能重复计算，也不能把同一份货发给两处。下游满仓时保留已完成批次，不丢货、不把批次偷偷变成金币。

### 复合产品的守恒口径

“一桶双拼”“一支星星棒”“一盒礼盒”不是相同数量单位，不能沿用所有件数直接相加的守恒式。建议为每个配方定义基础爆米花当量：例如双拼的当量等于其两份散料之和，礼盒当量等于所有组件之和。每次转换同时记录输入消耗与输出生成。

> **建议的不变量**
>
> 累计投入的基础爆米花当量 = 已售商品当量＋各阶段库存当量＋在制品当量。订单预留是库存子集，不再额外相加；初版不设损耗。

糖浆、调味粉、包装等初版为工艺表现，不开放独立经济库存。未来引入真实耗材时，需另建对应物料账，不能与爆米花当量混为一谈。

**不再把生产速率当作收入速率**

## 11 经济循环与增长动力

**高级设备只有在需求、交付与仓储也能承接时，才会形成真实经营收益。**

### 收入来自订单成交

单笔收入建议拆为商品销售收入与订单额外奖励。订单生成时固定报价；包装完成、配货未齐、礼盒组装与动画播放均不产生销售收入。金币余额加累计支出应等于累计收入，任何迁移补偿单独记账，不伪装成销售。

### 单价不是唯一价值指标

新品报价应综合消耗的基础当量、加工占用时间、仓储占用和订单机会。复合商品价值应能覆盖不直接出售组件的机会成本，但不能始终无条件优于单卖。用“订单完成收益／受限工位占用时间”等指标辅助平衡，而非只看每件售价。

### 客流与产能一起成长

示例推演：工厂能生产每秒 6 份，但客户平均每 10 秒只购买 10 份，长期需求仅为每秒 1 份，剩余产能不会自动变成收入。成长时应提高批量需求、接单承载与自动服务能力，而不是单纯要求更多拖动。

| **成长目标** | **建议奖励或用途** |
| --- | --- |
| 短期：完成眼前订单 | 金币、明确的交付反馈与当前任务完成感。 |
| 中期：买到新工艺 | 新品使用权、可见设备模块、首张新品体验订单。 |
| 长期：服务更多客户 | 常客纪念物、招牌或展示陈设；不立即新增专用货币。 |
| 后期：综合订单 | 礼盒、庆典客户与工厂代表作，继续消耗前代产品。 |

### 调参和模拟方法

分别模拟积极操作、低频操作、完全自动及先买非最优设备的路线；使用相同客流种子，统计首单、新品解锁、库存阻塞、空闲时长和现金回收。旧版 30／130／330／650 等价格属于旧循环，不能默认在新销售机制下仍合理。[\[S1\]](https://github.com/zhiba666/IAA/blob/052cfe85286e65c76598373a073f7b3bf13823b6/README.md)[\[S3\]](https://github.com/zhiba666/IAA/blob/052cfe85286e65c76598373a073f7b3bf13823b6/src/factory-rules.js)

本报告不定最终售价、升级费用或客流间隔。所有数值在版本实现后由确定性模拟与试玩共同确定，不以“更快赚钱”代替玩法验证。

**用可见变化表达经营结果**

## 12 界面、美术与反馈

**先让玩家看懂、拿得准、知道下一步，再增加装饰复杂度。**

### 场外界面信息层级

顶部保留真实金币、当前目标和场景切换；中部显示客户与订单，底部显示成品货架。客户订单应包含产品图标、名称、需求与已配数量、整单报酬。货架显示可用库存与订单预留，不能只显示含占用的总数。

首轮两个产品无需滚动货架。完整蓝图扩到七款时，先以当前营业菜单展示三到四款，其余按需查看；普通订单不超过两种商品。礼盒用一个独立成品图标表达，避免订单气泡无限增长。

### 三种信息不得混写

“工位能力”表示加工能力，“成品入库”表示真实包装产量，“销售收入”表示已成交收益。主动助力带来的实际产量与无人运行预测分开。未售库存不得显示为已获得金币或可保证收入。

| **反馈时点** | **视觉与声音建议** |
| --- | --- |
| 点击助力 | 操作部件响应、当前批次进度变化、短促轻音效；不伪造销售飘字。 |
| 拖动配货 | 产品拖影、可接收客户高亮、数量随目标变化、合法放入反馈。 |
| 订单成交 | 取货袋装满、客户带走商品、整单金币反馈；状态结算先于表现。 |
| 升级与新品 | 设备模块接入、第一次工艺演出、新品从出口出现，立即接续体验订单。 |

### 美术制作优先级

先制作原味／焦糖成品、裹糖模块、共享货架、两类客户和订单图标；再做后续设备与商品。沿用原有六代画面可复用部分，新增模块独立管理，不手改生成资源清单。构建与资源预算继续按仓库流程校验。[\[S1\]](https://github.com/zhiba666/IAA/blob/052cfe85286e65c76598373a073f7b3bf13823b6/README.md)

### 首轮不做的表现系统

不做复杂客户寻路、自由摆放店铺、多人拥挤队列、跨场景连续搬物或高级装饰商店。触控目标、短长屏、弹窗遮挡、取消回弹与加载失败恢复优先于装饰数量。

本报告的产品和设备描述是美术方向，不包含已经绘制的概念图，也不代表相应资源已完成。

**沿用权威核心，拆开生产与销售**

## 13 技术改造与状态边界

**新增玩法可以复用架构，但不能沿用“出货工位完成即售出”的旧含义。**

现有 Game 统一管理生产、库存与金币，是应保留的边界。当前 ship 完成批次会同步增加 totalSold 与收入，新方案须先将它改成包装完成与成品入库；客户订单才触发销售。[\[S1\]](https://github.com/zhiba666/IAA/blob/052cfe85286e65c76598373a073f7b3bf13823b6/README.md)[\[S4\]](https://github.com/zhiba666/IAA/blob/052cfe85286e65c76598373a073f7b3bf13823b6/src/core.js)

| **模块** | **建议改造方向** |
| --- | --- |
| factory-rules.js | 新增产品、配方、工艺、订单模板和自动化配置；代际标识保持稳定。 |
| core.js | 权威处理加工、库存、预留、订单生命周期、单次结算与迁移校验。 |
| main.js／platform.js | 手势明确分流；只发命令不改账；跨场景与前后台使用统一生命周期。 |
| interface／renderer／场景模块 | 两个视图读取同一快照；独立绘制订单、货架、工艺与反馈。 |
| production-insights.js | 区分加工产能、成品入库、销售与主动增益；预测纳入订单和仓容约束。 |
| tests／经济模拟工具 | 增加订单幂等、配方身份、库存竞争、自动路线与旧档保护回归。 |

### 建议的数据实体（新增设计，不是现有字段）

ProductDefinition：产品标识、包装单位、基础当量、解锁工艺。RecipeDefinition：输入输出、处理阶段、合法工位。Batch：批次标识、配方、数量、当前工序与剩余工作量。Order：订单标识、需求行、已预留行、固定报价、状态与结算标记。

临时拖拽预留和持久订单预留分开管理；从临时预留转为订单预留必须在一次合法提交中完成。预留不能被自动售货与加工重复使用。所有订单结算必须在同一状态事务中更新库存、账目和已结算标记。

### 点击不能快进整个世界

不可通过额外调用 game.tick 来实现点击助力，否则客户、运输、试运行等计时会一起前进。点击只修改目标加工的合法工作进度，真实时间仍由核心时钟统一推进。[\[S4\]](https://github.com/zhiba666/IAA/blob/052cfe85286e65c76598373a073f7b3bf13823b6/src/core.js)

代码命名与数据拆分为实现建议；未生成补丁、未修改仓库，也未声称新增字段已存在。

**新玩法不以损失旧进度为代价**

## 14 存档兼容与发布策略

**先隔离验证，再显式迁移；不把“只验证前两代”变成“删掉高代玩家工厂”。**

### 建议采用两个发布阶段

阶段 A：独立试玩入口与独立存档，验证两个场景、前两代和新结算。旧正式入口和原档仍可使用，不默认覆盖。阶段 B：完成经济对照、异常恢复与高代兼容后，才考虑替换正式入口。对外范围必须与实际上线能力一致。

### 版本与迁移规则

当前应用为 1.1.0，内部玩法标识为 v15，正式存档 schema 为 4。[\[S1\]](https://github.com/zhiba666/IAA/blob/052cfe85286e65c76598373a073f7b3bf13823b6/README.md) v1.3 是应用规划版本，不直接决定 schema 编号。新增库存与订单结构应使用显式新格式和迁移函数，不能只修改版本号后沿用旧校验。

| **旧状态** | **迁移原则** |
| --- | --- |
| 金币、历史收入与支出 | 保留原值；历史已售部分作为迁入期初账，不反推或重复生成旧商品。 |
| 设备代际与工位等级 | 不降级、不按新数组顺序误映射；高代工艺未实现时保持旧玩法可继续。 |
| 场内库存与在制品 | 明确映射为基础原味路线；保留已开始批次规格与工作进度，不重新计售。 |
| 已买物流与全自动收入 | 已有能力保留；正式迁入新销售玩法时为已全自动工厂提供基础售货能力，补偿单独记账。 |
| 未完成订单与拖动 | 持久订单预留可恢复；临时手势预留在保存边界取消；结算状态与钱、货同一快照保存。 |

### 写入失败与回退

迁移先备份，再写新档并回读验证；只有校验通过才切换运行模式。失败时旧工厂继续使用原数据，提供明确错误提示。新档恢复须校验产品合法性、数量、预留关系、工艺能力与结算状态，不能只检查 JSON 可读取。

### 高代旧档的硬性发布门槛

若第三至第六代新工艺尚未实现，不允许把对应旧档导入一个只能玩到第二代的正式模式。保持兼容入口或推迟强制切换，直到有明确映射及验收证据。首轮试玩无需提前承诺整个六代系统已完成。

迁移补偿、新存档键和最终格式号需由实现阶段确定。本报告不虚构已经存在的 v1.3 存档或迁移代码。

**先验证闭环，再扩展工艺**

## 15 开发顺序、风险与验收

**每一阶段必须能用真实订单、库存和收益演示，不以静态界面替代可玩结果。**

| **顺序** | **可交付结果** | **通过条件** |
| --- | --- | --- |
| P0-1 结算拆分 | 包装入库、成品库存、订单状态和一次性成交。 | 生产不发钱；配齐只发一次；取消不丢货。 |
| P0-2 场外体验 | 客户、货架、批量拖动、双场景和原味首单。 | 无需口头解释可完成；切屏不暂停另一场景或重复计时。 |
| P0-3 主动与自动 | 点击助力、早期物流、售货员与简单缺口补货。 | 手动与自动不争抢库存；无人操作可持续完成基础订单。 |
| P0-4 新品成长 | 裹糖工艺、焦糖桶、首张混合订单。 | 玩家能说明升级用途；买到后可立即生产新品。 |
| P1 扩展与发布 | 逐代实现双舱、淋酱、成型与组装；验证迁移。 | 各代能力真实有效；旧档、真机与经济回归通过。 |

### 必须覆盖的异常场景

重复松手与重复结算；拖动取消、切屏、多指和后台；自动售货与人工预留竞争；满仓与部分配齐；切配方时保留旧批次；同一组件不能既售出又组装；订单超过仓容；缺货补产不饥饿；旧档迁移写入失败；短长屏、音效与资源失败恢复。

### 体验验证与成功口径

建议先观察 6～10 位未玩过的新玩家，分别记录第一单是否需要帮助、购买第二代的原因、混合订单是否理解、自动化后是否主动安排下一步。小样本用于发现障碍，不据此宣布留存提升。后续再扩大样本，对照原版本验证。

核心事件建议包括首次包装、首次配货、首次成交、助力使用、自动化购买、新品解锁、新品首次成交、订单取消、满仓阻塞和存档失败。将“没有输入”与“正在思考或观看演出”区分，不能机械地把所有无操作时间都判为无聊。

旧版测试通过数量不是 v1.3 的验收结果。本版本必须重新构建、测试、运行经济模拟，并单独完成目标设备上的真实触控与恢复检查。[\[S5\]](https://github.com/zhiba666/IAA/blob/052cfe85286e65c76598373a073f7b3bf13823b6/docs/releases/v1.1.md)
