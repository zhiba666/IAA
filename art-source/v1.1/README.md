## 静态预览与验证范围

生成 36 个视图：首代在 320×524、360×640、390×844、430×932 的全屏、A拖拽、B拖拽、可投送、误投、设备弹窗、物流弹窗、扩建弹窗共 32 个；第六代在 320×524 和 390×844 的全屏与设备弹窗共 4 个。

所有金币、吞吐、价格、库存和升级状态是明确的合成布局样例，不是新经济配置。预览中的三种弹窗均居中；同一代、同一视口的机器、货仓和入口坐标在各状态保持一致。检查确认可见物体没有超出画布，64×64 入口示意框与货仓图形包围框不重叠。

320×524 采用独立的三排短屏美术布局样例；其余尺寸读取当前场景的装配位置。预览布局不是已实现的正式相机或触控契约，不能直接用这份样例替代 v1.1 全屏布局开发。源码 SHA 已随预览记录，便于辨别后来代码变化。

美术交付阶段已目检新增素材、三底、小尺寸、长屏拖拽/弹窗和短屏首代/六代。静态程序检查验证 PNG 尺寸、alpha、SHA、预算、物体边界、模态居中及场景坐标稳定；这一阶段的 QA 报告保留原始范围。后续运行时验证以正式构建和本轮输入回归报告为准，真机仍为 `NOT_RUN`。

## 运行接入与验证

全屏场景、HUD、居中模态、仅拖拽状态机和两段手势教学现已接入正式代码。手势指尖、真实数量、入口高亮与核心预留／提交／取消结果绑定；设备、物流、扩建窗口使用独立报价及模态输入层。

下一步优先进行抖音真机和新玩家体验验证。若真实操作中发现入口难辨认或设备比例无法复用，再定向补充对应资源。

## 重建美术预览

在仓库根目录执行：

```powershell
node art-source/v1.1/build-previews.cjs
node art-source/v1.1/verify-art.cjs
```

脚本只写本 `art-source/v1.1/` 目录。Sharp 依赖路径采用本机现有 runtime，迁移机器时需调整依赖路径。正式开发和用户已有的工作区修改不由这两个脚本更新。
