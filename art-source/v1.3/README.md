# 小小爆米花厂 v1.3 美术资源包

依据用户提供的《IAA_v1.3_版本设计思路报告》，补全客户直售、七款成品和六代工艺的美术缺口。报告中的评审流程及历史说明作为参考内容；资源制作后，已按用户后续要求完成正式游戏的美术接入。

后续新增的 [首二代工艺美术补充包](../v1.3-process/README.md) 独立提供空载裹糖机、焦糖散料、糖浆流、空焦糖桶，以及用于统一样式的原味散料，共 5 张图。本目录原 18 张静态资源已齐；补充包不加入本目录清单或正式预载，仅准备加工中间态，不表示完整机械拆层或玩法已经完成。

## 资源契约

- 使用内置 `image_gen`，每款资源独立生成。各子目录 `sources/` 保留原始 PNG，`prompts/` 和 `provenance.json` 保存完整提示词与修订记录。
- `manifest.fragment.json` 是各制作包输入；`manifest.json`、`catalog.js` 和 `runtime-manifest.cjs` 由构建生成。
- 新增资源路径为 `assets/art/v13/<id>.png`。清单包含尺寸、底部中心锚点、来源裁切矩形、源图/导出 SHA-256、压缩及 RGBA 解码大小、代际和使用状态。
- 导出只做真实 alpha 包围框裁切、等比 Lanczos 缩小及四周 4px 透明留边，不用程序抠背景、改色或画替代图。
- 商品长边不超过 256px，机器 640px，角色 384px，门脸 768px，取货袋 192px，订单图标 96px。运行时使用实际逻辑尺寸等比绘制。
- 七款商品的第一、二代可用于核心试玩；三至六代标记 `FUTURE_BLUEPRINT`，仅表示资源准备，不代表新品功能已实现。

## 构建与接入

```powershell
npm run art:v13
npm run art:v13:verify
npm run build
```

制作脚本需要 `sharp`。优先使用项目可解析的 `sharp`，其次使用本机 Codex 已配置的依赖路径；其他机器可通过 `IAA_SHARP_MODULE` 指定其模块路径。原始提示词、清单和生成记录在仓库内可追溯；AI 再次生成不保证逐像素复现，保存的源图可以确定性重做导出。

`npm run art:v13:verify` 校验源图和导出元数据、透明度、`assets/art/v13/` 副本、预览路径及脚本语法。静态脚本不运行浏览器或游戏交互。

`runtime-manifest.cjs` 是制作侧清单。标准 `npm run build` 现在通过 `tools/v13-art-build.mjs` 生成 `src/v13-art-manifest.js`，并把 18 张导出复制到 Web 与抖音包的 `assets/art/v13/`，校验尺寸、PNG 完整性和 SHA-256。原有 `tools/art-build.mjs`、87 张预载列表和预算不变。

正式游戏默认只加载原味成品和订单入口图标；HUD“新品”内有商品、工艺、直售三个页签。页面切换保留共用图片、释放离开页资源，当前选择最多 4 MiB RGBA 估算。原味成品用于真实流水线、货盘和拖影，装杯中的旧分层动画与加载失败回退保留。其余新品和直售资源是明确标注“筹备中”的展示，不产生订单、销售或金币。

直售展示复用共享货架的前后层与槽位，并加入原味杯放入取货袋的遮挡示意。这两处装配仅复用已有 PNG；取货袋前壁与提手的局部裁剪坐标由 `src/v13-showroom.js` 管理，后续换图须重新校准。
