# 小小爆米花厂 · 2.0.0

原生 Canvas + JavaScript 的轻经营流水线游戏。同一套正式入口生成浏览器和抖音小游戏包，无 npm 运行依赖。

当前循环：**观察生产瓶颈 → 比较改造影响 → 积压减少、出货加快 → 赚钱扩建**。2026-09-09 在现有 2.0 三段生产线上优化经营信息、现场操作与生产表现，沿用实际工作区及已审阅基线 `8e0d319`，没有再次重写生产核心。真机验收与软著办理继续暂停，不自动发布上线。

## 运行

需要 Node.js 18 或更新版本：

```powershell
npm run build
npm start
```

打开 [正式游戏入口](http://127.0.0.1:4173)。本地服务仅监听本机。进入后工厂自动运转；版本重构与旧档保留说明放在设置中。

主场景按「爆锅 → 装杯 → 出货」纵向连接，机器和两处实物积压始终对应真实生产状态。首页保留金币、实际出货、简短限制提示及一个扩建目标。点击工位打开紧凑底部操作区，比较设备能力、预计整线稳定出货和价格；并行数、批量、在制品等参数按需展开。可直接点击现场工位或底部标签切换，选中工位和库存仍可见。

购买后保留工位选中状态，操作区收成窄条，显示具体安装项目并留出观察空间。再次购买须明确点击「查看下一档」或切换工位查看新的报价；输入携带当前报价的工位、等级、价格及名称校验，重复点击、长按或旧报价不能直接购买下一档。金币不足、需先扩建和已满级分别显示原因。

键盘：`1 / 2 / 3` 直接切换对应工位，`Enter` 仅购买当前已确认的报价，收起后不会购买下一档；`M` 扩建，`S` 设置，`Escape` 关闭面板。没有点击产量、长按连点、火候操作或烧焦惩罚。`build:dev` 保留开发构建命令，但同样禁用连点和广告奖励。

## 生产规则

三个环节分别处理真实的份数：爆锅 → 待装杯库存 → 装杯 → 待出货库存 → 出货。两个仓位都有上限；完成的批次放不进下游仓位时留在工位，停止接新活；下游缺料时等待，批量工位需要凑齐该批份数才开工。

初始设备能力为爆锅 **4**、装杯 **2**、出货 **6 份/秒**，两个仓位各容纳 **12 份**。装杯首次改造 **30 金币**，能力提高到 **6 份/秒**。上游积压会下降，实际出货逐渐从约 2 份/秒提升到约 4 份/秒，随后受爆锅能力约束。

- 全部逻辑以整数「份」计量；杯、双杯、箱和货垛只表达同一批货的包装。
- 唯一货币为金币，固定 **1 份售出 = 1 金币**，只有出货工位完成后到账。
- `totalProduced` 表示累计投产份数，包含爆锅工位尚未完成的部分。始终满足：**累计投产 = 累计售出 + 两仓库存 + 三工位在制品**。
- 金币满足：**余额 = 累计出货收入 − 升级及扩建支出**。加工、包装和扩建没有额外产量或奖励。
- 「设备能力」是满料且不堵塞时的理论处理速度；「实际」是最近 10 秒完成的份数/秒（开局不足 10 秒使用已经营时间）。实际出货速度单独显示，不使用全局倍率推算。
- 模拟采用每秒 120 个固定时间量子，保存不足一个量子的余数、每条加工通道的批次及剩余时间。换代和升级保留现有库存及在制品，正在加工的批次完成后采用新规格。

## 经营提示与现场反馈

只读展示模块 `src/production-insights.js` 使用独立 `Game` 副本调用真实 `Game.tick`，复用并行工作头、整批开工、有限仓位与阻塞规则。副本从相同设备配置的空仓工况预热后测量稳定出货，**不把现有积压的短时释放算作可持续增长**。预测只按扩建阶段和设备等级缓存；金币、库存和每帧绘制不触发重复长模拟。正式金币、库存、进度、存档和事件不受推演影响。

瓶颈提示结合设备能力、真实批次、库存和持续处理记录；每 0.25 秒模拟时间采样，改造后保留约 2 秒观察确认，缺料或堵塞本身不会被直接判为瓶颈。相同能力的工位会提示共同限制。开局装杯改造展示「设备 2→6、整线稳定约 2→4 份/秒」；单独升级爆锅或出货则说明「暂不提高稳定出货，为后续改造预留能力」，仍可购买。

预计稳定出货与顶部最近 10 秒实测值分开。改造后的旧样本逐步退出窗口，期间标明均速更新状态；不会瞬间清空库存或用预测替换实测。安装效果出现在对应机器，随后货物积压和工作头动作继续读取真实生产。真实 `ship` 事件驱动成品离场、已到账收入提示及轻量声音，高频事件合并并限频，不逐份播放或重复结算。

后期并行设备表现为同一组机体及实际已购买的工作头。两处仓位用代表性爆米花和成品聚合显示，填充程度与数量对应实际库存。小屏优先收起次要信息，主要触控区至少 44×44 逻辑像素，布局考虑 320×524、390×844、抖音顶部胶囊和底部安全区；具体执行检查以本轮交付记录为准。

## 六代扩建与集中配置

所有价格、处理批次、并行通道、加工周期、仓位和解锁条件位于 [src/factory-rules.js](src/factory-rules.js)，本轮不调整。升级独立作用于所选工位；扩建卡显示两仓容量变化及开放的改造，明确说明「扩建开放改造，设备提速需另行购买」，不暗示扩建立即增加收入。

| 阶段 | 扩建金币 | 累计售出要求 | 曾达到实际出货速度 | 每仓容量 | 开放的主要结构变化 |
| --- | ---: | ---: | ---: | ---: | --- |
| 手摇锅 | 0 | 0 份 | 0 份/秒 | 12 份 | 自动三工位，先改造单头装杯 |
| 电热锅 | 180 | 100 份 | 3 份/秒 | 24 份 | 双锅、双头装杯、双份成组包装 |
| 双缸机 | 1,100 | 650 份 | 7 份/秒 | 48 份 | 连续双锅、双头加工、双道包装 |
| 多头机 | 4,200 | 2,600 份 | 12 份/秒 | 96 份 | 四锅并行、三头装杯、四份成箱 |
| 自动流水线 | 12,500 | 8,500 份 | 22 份/秒 | 192 份 | 双份加工、四道整箱出货 |
| 巨型爆米花塔 | 38,000 | 26,000 份 | 48 份/秒 | 384 份 | 六头加工阵列、高速整箱出货 |

扩建目标预先固定。速度达标在完整 10 秒采样后记录，已达标不会因之后的暂时堵塞而撤销；金币和累计售出仍须满足。六代后仍可改造并持续经营，不新增任务或货币。

## 新旧存档与替换边界

本轮保留存档版本 `2` 和键 `little_popcorn_factory_pipeline_v2`，不改变已有 v2 工厂进度。设置中说明 2.0 重构与旧档保留边界。旧键 `little_popcorn_factory_v1` 不读取、不改写、不删除、不迁移旧金币、不混用经济数据。设置中的重新开始只替换 v2 键；写入失败则保留当前工厂。

切到后台暂停生产，回来从保存的生产状态继续；重载不按离开时间补产或发钱。自动保存每 5 秒执行，购买、设置修改和进入后台也保存。进度属于当前浏览器来源或抖音本机存储。

旧合同、60%/40%分账、三次添料限制、能量与自动爆锅奖励、设备图鉴、品牌、广告入口、离线奖励及其结算已经移除。正式依赖中没有旧引导/经验/离线/设备模块，也没有原型覆盖安装器。平台 `reward()` / `interstitial()` 保留不可用接口，不创建广告 SDK 实例，即使本地保留广告位配置也不会请求或发奖。

旧 QA 页面和生成器已移除，旧数值分析脚本入口已停用。历史设计报告、软著材料与现有调研文档仅作记录，不作为当前规则或本轮验收依据。

## 抖音与浏览器构建

`npm run build` 同时生成 `web/game.bundle.js` 和 `build/douyin/`。将后者导入抖音开发者工具；保留原生画布、触摸、安全区、生命周期、本机存储、侧边栏适配与包内 WAV 音效，浏览器仍使用 WebAudio。

本地 `config.local.json` 继续使用原有配置，构建不会改写它。示例见 [config.local.example.json](config.local.example.json)。当前无需配置广告位；`preflight:strict` 只针对仍有效的构建与 AppID 要求。两个构建都强制关闭模拟广告及开发连点。
