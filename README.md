# 小小爆米花厂 · 双场景经营

原生 Canvas + JavaScript，同一源码构建浏览器与抖音小游戏。默认主玩法已整合为：**生产 → 包装入库 → 客户配货 → 整单收款 → 改造与自动化 → 持续经营**。无需模式参数。仅实现原味；焦糖、混合订单、新工艺及对应玩法尚未实现。已有多产品美术不代表玩法上线。包版本仍为 `1.1.0`，本轮不是完整 v1.3 发布。

## 运行与验证

需要 Node.js 18+，无 npm 运行依赖。

```powershell
npm run build
npm start
npm test
npm run preflight:strict
npm run simulate:orders
```

[浏览器主入口](http://127.0.0.1:4173/)和生成的 `build/douyin/game.js` 默认进入双场景。旧部署配置 `mode: v15`、旧订单试玩 URL 和废弃实验参数均不再启动独立试玩。建议新配置使用 `mode: factory-orders`。`config.local.json` 保持原样；配置示例见 [config.local.example.json](config.local.example.json)。本地服务默认只监听 127.0.0.1:4173。

## 操作与规则

- 生产区：将待装货盘拖入装杯入口，再将待包货盘拖入包装入口。包装只增加共享成品库存，没有运输到客户区的额外步骤，也不发金币。
- 直售区：将货架上的原味杯拖给客户，每次按可用库存、订单缺口、批量上限取最小值。首单一位客户，之后最多两位；需求和报价生成时固定。普通订单没有强制倒计时或失败罚款。
- 部分配货仍占仓、保持预留、没有收入。配齐后核心一次性扣整单库存、记销售和收入、移走订单；无需接单或再次点收钱。重复松手、重复事件及读档均不能重复成交。
- 免费取消未完成订单并释放预留。误投、多指、切屏、弹窗、失焦、缩放和后台取消临时拖拽，已成功配入订单的预留保持不变。
- 顶栏“点击助力”和“经营升级”是独立区域。助力面板选择工位，只推进该工位合法在制批次；不调用世界 tick，不缺料造货、不突破仓容、不直接加钱。停止点击后基础加工继续。
- 每段首次手动运输完成后，即可分别购买 A/B 自动转运。已购运输能力随改造和扩建保留。自动运输只取未被拖拽预留的货物。
- 首代可购买基础售货员。每个有限服务周期优先配能完成的单，再按等待时长排序。人工部分配货的订单必须明确点击“交给售货员”才会自动接续。售货员不会抢拖拽货物或其他订单预留。
- 补产先算订单未被库存和在制品覆盖的缺口，无缺口时补到目标库存。可用、预留、临时拿取和在制品分别计量；买齐 A/B 与售货员后，前台无人输入可持续生产成交。

键盘：`F` 生产、`O` 直售、`A` 助力、`U` 经营、`Escape` 关闭窗口或取消拖拽。切屏只换视图，共用唯一工厂、库存、账目与时钟；弹窗保持加工。切后台暂停，回来不补离线收益。

## 集中数值与经济

订单经济在 [src/order-rules.js](src/order-rules.js)，生产能力、物流规格与六代资源继续复用 [src/factory-rules.js](src/factory-rules.js)。价格由确定性模拟校验，没有照搬旧直接出货经济。

| 项目 | 本轮配置 |
| --- | --- |
| 订单模板循环 | 4 杯/4 金币，6/7，8/10，4/5 |
| 客户数量、单次配货 | 首单 1、之后最多 2；每次最多 4 杯 |
| 成品仓、目标库存 | 初始均为 24 杯；随物流等级同时升至 36、48、72 |
| A/B 自动转运 | 4 / 7 金币，各自完成首次手动教学后可购 |
| 基础售货员 | 12 金币；每 2 秒服务一次、最多配 4 杯 |
| 助力 | 每工位最多 4 次/秒；每次 0.1 秒加工进度；每秒最多额外 0.4 秒，持续上限 1.4 倍；同等进度对应产出随工位能力成长 |
| 爆米花设备各级价格 | 18、55、160、420、1200、3400 |
| 装杯设备各级价格 | 12、28、50、70、180、450、1300、3600 |
| 包装设备各级价格 | 20、50、140、400、1100、3000 |
| 物流三级价格 | 16、55、180；批量/入口/货盘容量为 36、48、72（还受代际规格影响），同步扩充成品仓与补产目标 |
| 第 2～6 代扩建价格 | 80、300、900、2600、7500 |
| 对应累计售出要求 | 80、280、800、2300、6600 杯 |

首次手动每段最多 4 份，之后基础整盘 24 份；A/B 自动周期仍为 1 秒，复用 120 Hz 核心时钟。扩建接回真实购买与成长，不要求玩家刻意停止操作；无人试运行只作为可选成就。升级保留已开工批次的规格，后续批次使用新能力。

购买同时更新命令、报价、支出账、能力预测和存档校验。正常经营始终满足 `金币余额 + 累计支出 = 累计收入`；包装量等于成品库存与已售数量之和（迁入历史由独立基线扣除）。迁入保留历史账目，不把旧金币计为新收入，不重造历史销售商品。没有额外赠送金币。

基础售货员按当前订单模板的稳定服务上限约为 **1.833 杯/秒、2.167 金币/秒**。设备改造提高加工能力；无人收入受售货服务能力封顶，预测明确显示这个限制。更高等级售货员与长期经济曲线不在本轮范围内。

## 确定性经济模拟

[tools/order-economy.cjs](tools/order-economy.cjs)只使用合法指令赚钱和购买，每一步检查实物与金币守恒；测试另覆盖满仓、部分配货、长期无人、重载等边界。模拟步长 0.25 秒，积极路线每 0.5 秒操作，低频每 8 秒操作；非最优路线每 2 秒操作，先改爆锅、买物流，再买自动化。

| 新档路线 | 首次成交 | 买齐 A/B/售货员 | 此时累计花费 |
| --- | ---: | ---: | ---: |
| 积极操作 | 3 秒 | 10.5 秒 | 23 |
| 低频操作 | 24 秒 | 64 秒 | 23 |
| 非最优购买 | 6 秒 | 34 秒 | 57 |

以下三条从**同一份已购 A/B/售货员存档**开始，再运行 600 秒，完全自动路线不注入任何人工操作：

| 路线 | 完成订单 | 售出原味杯 | 新收入 | 23 金币基础投入回本 |
| --- | ---: | ---: | ---: | ---: |
| 积极操作 | 262 | 1440 | 1701 | 9 秒 |
| 低频操作 | 218 | 1198 | 1415 | 14 秒 |
| 完全自动 | 200 | 1096 | 1294 | 14 秒 |

完全自动最后 60 秒仍生产、售出各 110 杯，成交 20 单，最长停单 4 秒；不是卖完初始库存即停止。这些是脚本结果，非真人教学时长；低门槛价格用于尽早验证可持续经营，尚未做真人留存平衡。

## 存档保护与兼容入口

新主档：`little_popcorn_factory_orders_v2`，订单 schema 2，内部继续复用经过校验的生产 schema 4。

没有新主档时，按已有正式 v4、正式 v2、订单 P0 的顺序发现来源。如果多个来源并存，界面明确提示其他旧档已保留，原文不被覆盖。废弃手动转运实验及更早的 `little_popcorn_factory_v1` 不自动导入或删除。

迁移流程：校验旧档 → 在新键前缀下备份原文 → 写迁移事务记录 → 写新格式 → 回读并通过核心校验 → 写提交标记 → 切换工厂。原存储键始终保留；已有不同备份不自动覆盖。事务未完成时，即使平台拒绝回退写入，下次启动仍选原来源，不启用半份迁移。旧正式迁移失败会继续运行原工厂；订单 P0 迁移失败暂停并可重试读取。损坏存档不会被新开局静默覆盖。

迁入保留金币、收入/支出历史、等级、已购能力、库存及在制批次。原已双段全自动的旧厂保留基础无人经营能力，并接续基础售货员；该接续能力记录在迁入基线中，不伪装成销售收入。六代合法旧工厂均有迁移和持续生产回归。

必要兼容入口仍保留：浏览器 [旧 v4 工厂](http://127.0.0.1:4173/?mode=legacy-v15)、[旧 v2 工厂](http://127.0.0.1:4173/?mode=baseline)；抖音可在本地配置中显式指定 `legacy-v15` 或 `baseline` 后重新构建。兼容入口使用各自旧存储键，不覆盖新主档。它们用于继续旧工厂及回归，不是新玩家默认玩法。不要同时在多个标签经营同一个存档。

删除了被替代的独立订单试玩启动分支、浏览器/抖音手动实验启动路由和订单零升级/零支出限制。保留原生产核心、兼容运行器、共用订单/场景模块、展页资源和有效保护性回归；内部历史文件名不是单独试玩入口。

## 构建与验证边界

`tools/build.mjs` 生成 `web/game.bundle.js` 和 `build/douyin/`。87 张基础 PNG、18 张按需商品/角色 PNG、3 张直售环境 PNG 继续走原构建校验，逐文件 SHA-256、尺寸和预算检查保留；源美术、参考图不随包发布。直售环境按场景加载，返回工厂释放。不要手改生成包或 `src/*art-manifest.js`。

运行代码兼容现有抖音编译约束：不使用可选链和空值合并。平台保留触摸、安全区、生命周期、存储、音效降级和禁用广告策略。默认入口的浏览器实际 bundle 与抖音 SDK 契约测试都覆盖单时钟、整单收入和后台暂停；SDK 模拟不是抖音真机。

本轮本地验证：`npm run build`、`npm test`（397 项全通过）、`npm run preflight:strict` 和订单经济模拟通过；Chrome 检查了 320×524、390×844 视口下的双场景、助力和经营面板。抖音开发者工具、抖音真机、设备实际内存/性能、真人新手观察均为 **NOT_RUN**。严格预检也不能替代账号后台、审核和设备验证。本轮未发布网站、创建 GitHub Release 或宣称完整 v1.3 已上线。
