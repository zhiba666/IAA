# 小小爆米花厂 · 2.0.0

原生 Canvas + JavaScript 的轻经营流水线游戏。同一套正式入口生成浏览器和抖音小游戏包，无 npm 运行依赖。

当前循环：**观察生产瓶颈 → 点击工位改造 → 积压减少、出货加快 → 赚钱扩建**。2026-09-08 本轮直接重构生产核心，真机验收与软著办理继续暂停，不自动发布上线。

## 运行

需要 Node.js 18 或更新版本：

```powershell
npm run build
npm start
```

打开 [正式游戏入口](http://127.0.0.1:4173)。本地服务仅监听本机。进入后工厂自动运转；首次说明不会暂停生产。

点击「爆锅」「装杯」「出货」的真实工位，查看能力、实际处理速度、在制品和下一次改造报价。购买后面板收起，可以直接观察生产线变化。顶部显示金币和一个当前扩建目标。

键盘：`1 / 2 / 3` 查看对应工位，`Enter` 购买当前工位改造，`M` 扩建，`S` 设置，`Escape` 关闭面板。没有点击产量、长按连点、火候操作或烧焦惩罚。`build:dev` 保留开发构建命令，但同样禁用连点和广告奖励。

## 生产规则

三个环节分别处理真实的份数：爆锅 → 待装杯库存 → 装杯 → 待出货库存 → 出货。两个仓位都有上限；完成的批次放不进下游仓位时留在工位，停止接新活；下游缺料时等待，批量工位需要凑齐该批份数才开工。

初始设备能力为爆锅 **4**、装杯 **2**、出货 **6 份/秒**，两个仓位各容纳 **12 份**。装杯首次改造 **30 金币**，能力提高到 **6 份/秒**。上游积压会下降，实际出货逐渐从约 2 份/秒提升到约 4 份/秒，随后受爆锅能力约束。

- 全部逻辑以整数「份」计量；杯、双杯、箱和货垛只表达同一批货的包装。
- 唯一货币为金币，固定 **1 份售出 = 1 金币**，只有出货工位完成后到账。
- `totalProduced` 表示累计投产份数，包含爆锅工位尚未完成的部分。始终满足：**累计投产 = 累计售出 + 两仓库存 + 三工位在制品**。
- 金币满足：**余额 = 累计出货收入 − 升级及扩建支出**。加工、包装和扩建没有额外产量或奖励。
- 「设备能力」是满料且不堵塞时的理论处理速度；「实际」是最近 10 秒完成的份数/秒（开局不足 10 秒使用已经营时间）。实际出货速度单独显示，不使用全局倍率推算。
- 模拟采用每秒 120 个固定时间量子，保存不足一个量子的余数、每条加工通道的批次及剩余时间。换代和升级保留现有库存及在制品，正在加工的批次完成后采用新规格。

## 六代扩建与集中配置

所有价格、处理批次、并行通道、加工周期、仓位和解锁条件位于 [src/factory-rules.js](src/factory-rules.js)。升级独立作用于所选工位；扩建增加仓位并开放新的工位改造，不重置旧设备。

| 阶段 | 扩建金币 | 累计售出要求 | 曾达到实际出货速度 | 每仓容量 | 开放的主要结构变化 |
| --- | ---: | ---: | ---: | ---: | --- |
| 手摇锅 | 0 | 0 份 | 0 份/秒 | 12 份 | 自动三工位，先改造单头装杯 |
| 电热锅 | 180 | 100 份 | 3 份/秒 | 24 份 | 双锅、双头装杯、双份成组包装 |
| 双缸机 | 1,100 | 650 份 | 7 份/秒 | 48 份 | 连续双锅、双头加工、双道包装 |
| 多头机 | 4,200 | 2,600 份 | 12 份/秒 | 96 份 | 四锅并行、三头装杯、四份成箱 |
| 自动流水线 | 12,500 | 8,500 份 | 22 份/秒 | 192 份 | 双份加工、四道整箱出货 |
| 巨型爆米花塔 | 38,000 | 26,000 份 | 48 份/秒 | 384 份 | 六头加工阵列、高速整箱出货 |

扩建目标预先固定。速度达标在完整 10 秒采样后记录，已达标不会因之后的暂时堵塞而撤销；金币和累计售出仍须满足。六代后仍可改造并持续经营，不新增任务或货币。

## 新旧存档与替换边界

新版本只读写 `little_popcorn_factory_pipeline_v2`，存档版本为 `2`。首次进入明确说明从新工厂开始。旧键 `little_popcorn_factory_v1` 保留，不删除、不迁移旧金币、不混用经济数据。设置中的重新开始只替换新版本的键；写入失败则保留当前工厂。

切到后台暂停生产，回来从保存的生产状态继续；重载不按离开时间补产或发钱。自动保存每 5 秒执行，购买、设置修改和进入后台也保存。进度属于当前浏览器来源或抖音本机存储。

旧合同、60%/40%分账、三次添料限制、能量与自动爆锅奖励、设备图鉴、品牌、广告入口、离线奖励及其结算已经移除。正式依赖中没有旧引导/经验/离线/设备模块，也没有原型覆盖安装器。平台 `reward()` / `interstitial()` 保留不可用接口，不创建广告 SDK 实例，即使本地保留广告位配置也不会请求或发奖。

旧 QA 页面和生成器已移除，旧数值分析脚本入口已停用。历史设计报告、软著材料与现有调研文档仅作记录，不作为当前规则或本轮验收依据。

## 抖音与浏览器构建

`npm run build` 同时生成 `web/game.bundle.js` 和 `build/douyin/`。将后者导入抖音开发者工具；保留原生画布、触摸、安全区、生命周期、本机存储、侧边栏适配与包内 WAV 音效，浏览器仍使用 WebAudio。

本地 `config.local.json` 继续使用原有配置，构建不会改写它。示例见 [config.local.example.json](config.local.example.json)。当前无需配置广告位；`preflight:strict` 只针对仍有效的构建与 AppID 要求。两个构建都强制关闭模拟广告及开发连点。

## 技术检查

```powershell
npm test
npm run build
npm run preflight
npm run preflight:strict
```

`npm test` 会先生成正式 release 构建，确保双端整包测试使用当前源码。本轮检查覆盖库存与金币守恒、堵塞/缺料/恢复、独立工位升级扣款、在制品跨升级保存、固定扩建目标与六代可达性、不同时间步及存档重载、旧键隔离、后台无补算、废弃入口无效、小屏安全区及浏览器/非 DOM 抖音宿主。具体已执行结果记录在 [当前开发重心](docs/DEVELOPMENT_FOCUS.md)。

浏览器只读诊断为 `__POPCORN__.snapshot()` 和 `.analytics()`；没有修改金币或生产的调试入口。本地诊断不联网，除非明确在本地配置启用已有平台埋点。

## 文件分工

| 文件 | 职责 |
| --- | --- |
| `src/factory-rules.js` | 冻结的六代阶段与工位数值配置 |
| `src/core.js` | 唯一生产模拟、守恒、升级扩建、存档与首次瓶颈提示 |
| `src/production-scene.js` | 读取批次进度，绘制机器、并行通道与有限库存 |
| `src/interface.js` | 金币、一个扩建目标、工位面板、短提示和小屏布局 |
| `src/renderer.js` | Canvas 基础绘图与命中区域 |
| `src/main.js` | 正式双端入口、输入、生命周期与自动保存 |
| `src/platform.js` / `src/audio.js` | 保留的平台适配、声音与降级 |
| `tools/build.mjs` / `tools/bundle.mjs` | 双端构建与共用打包 |
| `tests/` | 新规则技术回归及保留的平台检查 |
