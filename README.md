# 小小爆米花厂 · v1.1

原生 Canvas + JavaScript 轻经营流水线游戏，同一正式入口构建浏览器与抖音小游戏包。**v1.1**（包版本 `1.1.0`）围绕全屏工厂、紧凑 HUD、居中改造窗口和仅拖拽搬运改进操作：按住货盘 → 拖入对应入口 → 真实加工与出货 → 分别购买两段自动转运 → 调整产能、完成自动试运行 → 扩建。正式存档继续使用 schema 4，内部 v1.5 玩法标识和已有经济规则保留；应用版本与存档版本相互独立。

## 运行与检查

需要 Node.js 18 或更新版本，无 npm 运行依赖。

```powershell
npm run build
npm start
npm test
npm run preflight
node tools/automation-balance.cjs
```

[浏览器正式入口](http://127.0.0.1:4173/)默认进入两段拖拽搬运与自动化，使用 schema 4，并兼容迁移已有 v2 工厂。历史对照模式供回归使用，不作为新玩家入口。

本地服务器只监听本机。`npm test` 先构建源码；`preflight:strict` 提供更严格静态检查，不能替代真机验证。`build:dev` 仍禁用连点产量和模拟广告。

`tools/build.mjs` 生成 `web/game.bundle.js` 与 `build/douyin/`，从原六代冻结合同的 84 张 PNG 和 [v1.1 独立补充合同](art-source/v1.1/manifest.fragment.json)的 3 张 PNG 生成清单，共 87 张。新图包含教学手势、地板延展和墙角层；旧合同与图片保持原样。构建检查两端尺寸、逐文件 SHA-256 及首代/总资源/解码预算；当前资源合计 1,928,459 B，RGBA 基础估算 28,400,528 B。源图、整屏参考图及预览不随包发布。不要手改生成包或 `src/art-manifest.js`。本地 `config.local.json` 不被构建改写，格式见 [配置示例](config.local.example.json)。

构建器只合并模块，不转译 JavaScript。`src/` 的运行代码需兼容抖音真机编译器：用显式判空代替可选链（`?.`）和空值合并（`??`），即使 IDE 已开启 ES6 编译也不能直接使用这两种语法。修改源码后运行 `npm run build`，在抖音开发者工具中使用 `build/douyin/` 项目。

复用的首代装配数据位于 [活动装配目录](art-source/six-gen/integration/legacy/README.md)。当前构建无需 `archive/` 或 `IAA-six-gen-integration` 临时工作树；历史归档可单独存放。

## 正式玩法

三个工位和两段运输组成完整链路：

```text
爆锅 → 待装仓 → A 段搬运 → 装杯进料位 → 装杯
     → 待发仓 → B 段搬运 → 出货进料位 → 出货结算
```

按住货盘，拖到对应进料口松手。手动搬运只通过拖拽提交；货盘携带实际可搬数量，合法入口随当前运输段高亮。每段首次手动最多 4 份，此后整盘最多 24 份，实际份数还受库存和入口余量限制。点击后松手、取消、误投、双指、打开设置、缩放及切后台会释放预留，货物仍在源仓；搬运只进入下一工位的输入位，不能跳过加工或直接卖货。

| 购买 | 初期配置 | 收益 |
| --- | --- | --- |
| 设备改造 | 装杯 30 金币：2→3 份/秒；后续 90 金币到 4、180 金币到 6 | 提高该工位处理能力，整线是否提速另行预测 |
| 自动转运 | A 段 130 金币，B 段 330 金币，分别购买 | 永久省去对应搬运动作；已购能力随扩建保留 |
| 整盘与仓位 | 首次 60 金币：24→36 份 | 同步增加批量、两个入口及输出仓容量，减少补料频率 |

新开局爆锅/装杯/出货能力为 4/2/6 份每秒，两仓和两个入口各 24 份。自动运输按 120 Hz 核心时钟每 120 ticks 转运一批；后续批量与容量随物流等级和机器阶段增长。旧档使用明确的兼容规格，保留原升级能力。

第一扩建需要两段自动接通、自动试运行完成、累计真实销售 1200 份和 650 金币余额。试运行在最近 10 秒没有手动转运、两段自动已接通至少 10 秒后，连续 45 秒保持实测出货至少 3 份/秒，设备和运输能力也须达到这一门槛。达成里程碑永久保留；完成自动化后，前台持续不操作仍会生产。

当前配置集中在 [factory-rules.js](src/factory-rules.js)。[经济模拟](tools/automation-balance.cjs)的三条操作/购买路线首次销售均约 3.17 秒，两段接通分别在 3:08、4:01、4:14，首次扩建在 6:19、7:08、7:23。这些是确定性脚本结果，尚不代表真人完成时间；首段自动化的低频和非最优路线仍略晚于方案的 1～2 分钟候选区间。

## 生产、预测和交互边界

只有 `Game` 修改库存与金币，1 份真实售出结算 1 金币。守恒关系为：投产 = 售出 + 两个输出仓 + 两个输入位 + 三工位在制品；金币余额 + 累计支出 = 累计销售收入。预留货物仍占源仓空间，自动运输只取未预留库存。缺料等待，满仓保留完成批次，升级保留旧批次规格。

设备能力、自动运行基线、最近 10 秒实测出货分别展示。任意运输段尚未自动接通时，自动运行基线为 0；有限手动库存产生的销售继续计入实测。预测器使用隔离空工厂和真实生产规则，纳入运输周期、批量、入口、仓容、机器等级及旧档成长配置，提供设备/物流/自动化/扩建的前后预测。

点击工位打开居中的设备改造窗口，在“物流改造”分别购买自动化和整盘扩容。工位报价绑定工位、等级、价格和名称，购买后需要重新查看下一档。拖动松手不会再触发购买窗口。HUD、场景和模态窗口独立布局，打开窗口保持机器位置稳定，并优先处理窗口输入；主要触控区至少 44×44 逻辑像素，转运入口使用更大的目标区域。

键盘 `1/2/3` 切换工位，`Enter` 提交当前确认报价，`L` 物流、`M` 扩建、`S` 设置、`Escape` 关闭窗口或取消搬运。鼠标与触屏均使用按住、拖动、松手的搬运操作。

## 存档与平台

正式存档键为 `little_popcorn_factory_automation_v4`。首次迁移时保留 `little_popcorn_factory_pipeline_v2` 原文，备份到 `little_popcorn_factory_automation_v4_backup_v2`，新档写入并回读一致后才切换运行工厂。失败时原工厂继续运行；迁移不会重新锁成手动、改低旧等级或销毁已有批次。正式模式不读取或删除 P0 和旧 `little_popcorn_factory_v1`。详细边界见 [1.5 存档迁移说明](docs/AUTOMATION_V15.md#存档迁移)。

后台暂停，返回继续，不按离开时长补产发钱。重开只写当前模式的存档键，写入失败保留当前工厂。浏览器用 WebAudio；抖音保留触摸、安全区、生命周期、存储与包内音效降级。广告接口不可用，不创建广告实例。

点击产量、火候惩罚、合同、分账、能量、广告、离线奖励、侧边栏等已退役系统保持停用。抖音真机、设备性能和真人新手观察仍为 **NOT_RUN**。本轮为源码实现与本地验证，不代表 GitHub Release 已创建或抖音平台已上线。
