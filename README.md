# 小小爆米花厂 · 1.0.0

一款竖屏、单指操作的爆米花工厂增量游戏。原生 Canvas + JavaScript 实现，无 npm 运行依赖；同一套玩法代码生成浏览器试玩和抖音小游戏包。

**当前安排（2026-09-08）：暂缓真机验收与软著办理，着重打磨游戏体验。** 优先改善首局引导、成长节奏、操作反馈和界面细节，验证以浏览器、IDE 和适用自动测试为主。暂停事项待用户明确恢复后继续；详见[当前开发重心](docs/DEVELOPMENT_FOCUS.md)。

## 当前玩法

- **边操作边学的首局引导**：直接指向锅、可购买的升级和装车按钮；首次升级后再点一次看增产，自动火力升级后松手观察连续出货。帮助不自动弹出或暂停生产，实际练习进度随存档保存，可跳过并从「引导」恢复。详见[操作引导](docs/ACTION_ONBOARDING_2026-09-08.md)。
- 六代机器从小锅成长到爆米花塔，保留基础点击、自动生产、三类永久升级与批量升级。
- 前六张订单教会生产与换代；双缸机后，每次从**影院量产、精品糖衣礼盒、庆典爆发**中选择一张合同，做到第 20 单竣工。
- **六件设备、永久收集、同时生效**：双缸机开放设备图鉴，显示全部设备用途、条件和进度。完成第 7 单获得装箱臂与糖衣机，完成第 8 单获得蓄压罐，换上多头机获得自动送料器；热能回收器、质检台可通过出锅和合同收集提前获得，也分别由第 13、16 单兜底。达标自动获得，无槽位、装卸或接单锁配。首页显示下一件目标，设备安装后持续出现在工厂。
- 装箱臂保留常规产出的 **60% 合同／40% 零售**分配，额外生产相当于常规产出 **15%** 的合同货物；糖衣机提高加工速度 150%；蓄压罐默认每次满锅自动增产 25%。送料器每锅自动追加一次添料，回收器提高自然蓄能速度 10%，质检台提高新合同基础奖金 5%。具体边界与获取条件见[永久设备收集设计](docs/EQUIPMENT_COLLECTION_2026-09-08.md)。
- 合同占用的货物暂不出售，交付时一次结算货款与奖励。放弃合同需再次确认，当前进度和待结货款随之清空。
- 能量达到 **100** 自动免费爆锅，自动生产与添料持续蓄能。双缸机后每锅最多添料三次，每次间隔一秒；送料器不消耗手动额度。蓄压罐默认自动放锅，可在图鉴选择「手动储压」留一锅备用，切回自动会立即释放已存锅。全主线可用自动生产完成，无需主动添料、手动放锅或观看广告；玩家仍需升级、接单和交付。已移除手动提前点火和完美火候判定。
- 教学奖励自动到账；删除新档中的研发、工艺、生产档位、分段交付、并行委托与无限返场。旧存档已获得的永久加成保留，符合旧领取条件的未领成果迁移时结算一次。
- 五类可选激励、品牌永久加成、离线收益、经营记录和三件竣工陈列保留。广告只翻倍离线现款，合同待交货款不重复发放。

当前设备规则、获取节奏、旧存档与离线边界优先阅读[永久设备收集设计](docs/EQUIPMENT_COLLECTION_2026-09-08.md)，首局教学见[操作引导](docs/ACTION_ONBOARDING_2026-09-08.md)。[合同改版](docs/FACTORY_REDESIGN_2026-09-08.md)和[渐进引导](docs/ONBOARDING_2026-09-08.md)保留上一轮设计及当时验收；其中两槽配装、流水线专属放锅与自动说明队列已被当前规则替代。[移除完美判定](docs/AUTO_BURST_SIMPLIFICATION_2026-09-08.md)保留自动爆锅调整背景。

## 立即试玩

需要 Node.js 18 或更新版本。在此目录运行：

```powershell
npm run build
npm start
```

打开[本地试玩](http://127.0.0.1:4173)。服务只监听本机。也可直接打开 `web/index.html`，浏览器存储策略可能因 file 协议而不同，建议使用本地服务。

启动后阅读健康游戏忠告，点击「开始经营」进入工厂。点击机器或机器下方空地添料，场景左侧查看当前目标，右上查看主线合同与设备图鉴，场景底部查看下一件设备进度和自动出锅进度。选择手动储压且已有存锅时，底部提供「放出整锅」。

底部入口随进度开放：「升级」提升基础产能，「合同」选客户和交付，「成长记录」查看自动到账的教学记录，「工厂」查看换代、设备图鉴、品牌合作与竣工陈列。顶部「引导」只列已解锁功能，可随时回看用途；设置始终可用。第七单开始先选合同，再按要求生产；设备获取自动记录，合同进行中也可查看图鉴、切换放锅模式。小屏展开引导时可能暂藏首页图鉴快捷入口，可经「工厂 → 设备图鉴」进入。

电脑支持空格添料、1/2/3 升级、O 合同、M 换代、Q 教学记录、B 品牌合作、P 设备图鉴、R 释放蓄压、Escape 关闭面板。启动忠告期间不能用快捷键跳过开工。

新玩法验视可运行 `node tools/factory-check.mjs`，打开[合同试玩页](http://127.0.0.1:4173/factory-check.html)。它使用明确标识的内存夹具，可切换六代设备与小屏、正常游玩或加速检查；不会读写正式存档。

浏览器使用模拟激励，可选择完整观看、中途关闭或加载失败，没有真实广告流量。新档交付首单且营业满 90 秒后开放可选激励，激励之间无固定冷却，播放中拦截重复请求，普通成长始终可用。进度属于当前浏览器和来源，不跨设备同步；卸载或清理应用数据会影响存档。需要重新试玩时，打开「设置 → 删除存档并重新开始」，确认一次即可清空本设备游戏进度和设置，从新手引导开工；删除后无法恢复。

## 开发长按连点

开发阶段快速体验成长流程，运行 `npm run build:dev`，再用 `npm start` 试玩，或将生成的 `build/douyin/` 导入抖音开发者工具并预览到手机。

在机器或可点击生产区域按住 **350 毫秒** 后，持续按住视为 **每秒点击 100 次**；按下时仍立即正常生产一次。松手、移出生产区域、打开面板、切入后台或窗口尺寸变化都会停止连点。升级、订单和广告等按钮仍按原来的单次操作处理。产出、能量、教学进度按真实规则累计；双缸机后仍遵守每锅最多三次、间隔一秒的添料限制。调试获得的进度会正常保存。

`build:dev` 在浏览器与真机包中开启 `developerHoldTap`。该开关由构建命令决定，`config.local.json` 的同名值会被覆盖；示例里的 `false` 是发布默认值。开发包和发布包使用同一输出目录，切换后需重新加载游戏。**发布验收前运行 `npm run build`，它会强制关闭长按连点；`npm run preflight` 会拒绝仍开启该功能的开发包。** 此功能用于开发调试，不属于正式玩法。

## 抖音小游戏包

`npm run build` 生成 `build/douyin/`，包含 `game.js`、`game.json`、`project.config.json`、`config.js`、`game.bundle.js`。在抖音开发者工具中导入该目录进行联调。

需要联调时，在根目录创建已被 Git 忽略的 `config.local.json`，填写自己已开通的配置：

```json
{
  "appId": "你的 AppID",
  "rewardAdUnitId": "你的激励视频广告位 ID",
  "interstitialAdUnitId": "你的插屏广告位 ID",
  "analyticsEnabled": false
}
```

再次构建会读取此配置并写入发布目录，生成目录里的修改会在下次构建时被覆盖。抖音构建强制禁用模拟奖励；未填写广告位 ID 时返回不可用，生产与普通结算继续工作。抖音使用包内 WAV 原生音效，浏览器使用 WebAudio，不支持对应音频 API 时安全降级。

个人开发者账号已认证，小游戏已创建，真实 AppID 已写入本地配置。平台基础资料（介绍、分类、美食题材和图标）已保存为草稿；软著尚未办理，自审尚未完成，两个广告位仍为空。

支持的原生宿主显示「侧边栏再来玩」，设置中也可打开复访指引；只有用户点击才跳转，不发放金币或承诺礼包，导航成功不等于已从侧边栏返回。不支持该能力的宿主隐藏入口。**2026-09-06 用户已确认 Android 侧边栏问题来自未上线游戏的平台限制，原因定位结束，不再列为待排查代码故障。** 待用户恢复真机验收、且上线或测试加白解除限制后再复验。

既有 IDE、Android 操作与侧边栏证据见[抖音联调准备](docs/DOUYIN_SETUP.md)；历史版本验证不覆盖后续界面。长后台离线、长时性能、iOS 和真实广告仍待测，真机验收与软著办理继续暂停。恢复手机测试时，授权入口为后台「开发 → 开发设置 → 测试管理 → 添加设备」，由试玩的抖音账号扫码；见官方[小游戏测试设备说明](https://developer.open-douyin.com/docs/resource/zh-CN/mini-game/develop/dev-tools/game-debug/bonus-scene)。

`npm run preflight` 检查包结构与本地配置；`npm run preflight:strict` 还会将缺失广告位列为未就绪。这些检查不能替代平台权限或手机验证。
